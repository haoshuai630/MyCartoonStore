# 08 · PRD 平移对照表

> 课程 PRD 是照着 MyPetStore 写的。本文逐条记录：**哪些照搬、哪些改写、为什么改、影响到哪里**。
> 用途：写代码时对数、答辩时解释"为什么和老师给的不一样"。

---

## 1. 平移原则

| 原则 | 说明 |
|---|---|
| 机制不动 | 会话、归属校验、持久化购物车、事务、状态机、乐观锁、并发规则——全部照搬 |
| 语义替换 | 宠物→漫画作品，宠物/用品→单行本/周边，其余术语表见 §2 |
| 结构不动 | 七张表的字段、约束、索引、CHECK 一字不改 |
| 只减不增 | 原型里没实现的能力一律删除入口，不新增"看起来能用"的功能 |
| 可追溯 | 每条改动在 §4 有编号、理由、影响面 |

## 3. 保持不变的清单

以下内容**完全按 PRD 执行**，不做任何调整：

1. 两个独立 Spring Boot 工程，端口 8080 / 8081，服务端渲染。
2. 两端共享一个 MySQL 库的七张业务表，不通过 HTTP 互调业务。
3. 购物车存数据库，Session 只存身份与临时结算确认。
4. 一个商品一个 SKU，不做多规格；下架代替删除。
5. 两级分类，商品只能挂二级，编码与父子关系创建后不可变。
6. 单 SKU 数量 1–99，每车最多 20 种，重复加入累加。
7. 整车结算，无勾选、无运费、无优惠、无税。
8. 下单扣库存、支付不扣、取消恢复一次；待支付无自动过期。
9. 订单五状态与全部时间字段约束。
10. 商品 `version` 乐观锁；补货只能增量。
11. 金额 `BigDecimal` + `DECIMAL(12,2)`；订单快照不回写。
12. 首页新品 3 / 精选 4；列表默认 6 条、页大小 1–50。
13. 403/404/400/500 的处理口径与文案原则。
14. 32 个 P0 验收场景的**判定逻辑**。

## 4. 改动清单

| 编号 | 项目 | PRD 原文 | 本项目 | 理由 | 影响 |
|---|---|---|---|---|---|
| D-01 | 业务域 | 宠物及宠物用品 | 漫画作品及官方周边 | 指导书允许自选业务；本人兴趣与素材可控 | 全部文案与种子数据 |
| D-02 | 一级分类语义 | 犬类、猫类、水族、鸟类、爬宠 | 5 部虚构作品 | 漫画店的核心入口是作品，不是物种 | 首页、列表侧栏、面包屑 |

| D-05 | 二级分类名称 | 宠物 / 用品 | 单行本 / 官方周边 | 对应关系最自然 | 分类种子、页面文案 |

| D-16 | 首页"本周热卖" | 移除 | 移除 | PRD 明确要求 | 首页少一个区块 |

| D-18 | 素材目录 | `images/products/{sku}/1.jpg` | `images/products/{sku}/cover.svg` + `1..3.svg` | 统一命名 | 种子数据路径 |

## 7. 答辩可能被问到的问题

**Q1：为什么改业务？是不是没跟着视频做？**
> 指导书"实验步骤"第 2 条写明：采用与课程不同的业务和设计，可以不参照视频完成。我保留了 PRD 的全部业务机制（事务、状态机、并发、归属校验），只替换领域语义，验收标准仍然逐条对齐 AC。

**Q2：七张表能装下漫画业务吗？**
> 能。`category` 两级装"作品 + 单行本/周边"，`product` 一 SKU 装"某一卷或某件周边"，`product_image` 装相册。没有新增字段，说明领域模型是通用的。

**Q3：为什么类型不用新字段？**
> PRD 明确要求类型来自既有二级分类、不新增字段。我用二级分类 `code` 的后缀 `-COMIC` / `-MERCH` 做判定，既满足约束，又能被程序校验（新增二级时强制后缀）。

**Q4：一个商品一个 SKU，那"同一件周边不同尺码"怎么办？**
> 本期不做多规格，这是 PRD 的明确约束（CON-06）。尺码差异如果要表达，只能建成不同 SKU 的商品，但本期不建。

**Q5：两端怎么保证一致？**
> 只共享数据库，各自事务。用户端下单扣库存，后台补货用原子 `UPDATE stock = stock + ?`，都基于数据库最新值，`version` 递增，不靠应用内锁。

**Q6：为什么 P1 全做？**
> 四项成本递增，先做资料改密（页面已存在），最后做相册维护；文档里写了砍功能线，时间不够按顺序放弃，不影响 P0。
