# 漫屿 MANGA ISLE · MyCartoonStore

> 一个用 SSM（Spring Boot + Spring MVC + MyBatis-Plus）实现的**原创漫画 + 官方周边**自营商店。
> 用户端购物 + 管理端 CMS，两个独立工程，共享一个 MySQL 库的七张业务表。

本文档集是《软件开发架构平台》实验一的**项目开发文档**，在课程提供的 MyPetStore PRD、实验指导书、七表 SQL 和用户端原型基础上，把业务域平移到"漫画及其周边"，并锁定全部实现口径。

## 4. 十二个已锁定的决策

1. **业务域**：宠物商城 → 漫画及其周边。技术骨架、七表结构、交易规则全部保留，只换语义与素材。
2. **分类**：两级。一级 = 作品 IP（5 部），二级 = 单行本 / 官方周边。商品只能挂二级。
3. **类型**：`productType ∈ {ALL, COMIC, MERCH}`，由二级分类 `code` 后缀（`-COMIC` / `-MERCH`）推导，**不新增数据库字段**。
4. **工程**：一个仓库、Maven 多模块。两个独立启动的应用（用户端 8080、管理端 8081），业务规则放在共享模块里只写一遍；不通过 HTTP 互调业务。详见 09 篇。
5. **会话**：两端各自 Servlet Session，Cookie 名不同，一端退出不影响另一端。
6. **购物车**：数据库持久化，Session 不存购物车副本；不预占库存；整车结算，无勾选。
7. **下单**：一次事务完成"写订单 + 写明细 + 扣库存 + 清结算条目"，同成同败。
8. **库存**：下单扣、支付不扣、取消恢复一次；后台只能增量补货，不能改绝对值。
9. **并发**：商品 `version` 乐观锁 + 用户行锁 + 订单行锁，见 02 篇 §6。
10. **金额**：只算商品明细合计，无运费、无优惠、无税；订单存快照，商品改价不影响历史。
11. **支付**：显式"模拟成功/失败"，成功写 `MOCK` + 唯一 `payment_no` + `paid_at`。
12. **诚实展示**：不出现销量、榜单、物流轨迹、优惠券、积分、假统计等未实现功能入口。

```

├── pom.xml
├── cartoon-common/                  # 异常、分页、金额、枚举、SessionUser、CSRF
├── cartoon-catalog/                 # 分类、商品、相册
├── cartoon-account/                 # 账号、登录校验、资料
├── cartoon-cart/                    # 购物车
├── cartoon-order/                   # 结算确认、订单、取消
├── cartoon-payment/                 # 模拟支付
├── cartoon-user-web/                # 用户端应用，8080
├── cartoon-admin-web/               # 管理端应用，8081，context-path=/admin
├── cartoon-test-support/            # 测试库与测试工具
├── docs/                            # 本开发文档
├── demo/                            # 分类结构对比静态站点
└── reports/                         # 每模块开发汇报与证据
```
