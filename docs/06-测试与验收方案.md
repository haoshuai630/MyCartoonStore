# 06 · 测试与验收方案

> 本文件是**验收设计**，不是测试报告。每条 AC 都要求记录：操作、预期、实际结果、必要的请求/数据库证据。

## 3. 怎么测（方法要求）

### 3.1 单元测试

- 覆盖：金额计算、数量边界、状态迁移合法性、分页参数归一、分类层级校验。
- Mock Mapper 只能验证分支，**不能证明真实 SQL 与数据库**。

### 3.2 集成测试（真实数据库）

- 使用可恢复的测试数据；每个用例前后核对库存、版本、订单数。
- 事务失败必须在**真实业务事务入口**注入（例如在 Service 内抛异常），不能用外层测试事务掩盖边界。

### 3.3 并发测试

- 两个独立连接 / 两个线程，带明确同步起点（`CountDownLatch`），不是"连点两次"。
- 必须验证：同一车并发提交只成交一次；支付与取消只有一个成功；用户买 2 与后台补 3 并发后库存为 11。
- AC-28 必须**两个应用实例同时运行**，单进程两次调用不算跨工程证据。

### 3.4 手工验收

- 用 Chrome / Edge，1366×768 与 1920×1080 各走一遍主流程。
- 每个 AC 记录：时间、账号、操作、页面截图或请求、数据库前后查询结果。

## 4. 证据要求

| 证据 | 说明 |
|---|---|
| 交易证据 | 操作前后的订单、明细、库存、版本、购物车结果（SQL 截图或导出） |
| 权限证据 | 越权请求的响应码 + 目标数据未变化的查询结果 |
| 事务证据 | 注入异常后五处数据同时回到原值 |
| 并发证据 | 两个终端的日志时间戳 + 最终库存/状态 |
| 复现证据 | 空库初始化日志 + 两端启动日志 + 首页截图 |

成功提示页**不能**单独作为原子性证据。
