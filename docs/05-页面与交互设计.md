# 05 · 页面与交互设计

---

## 1. 设计原则

1. **一个页面只回答一个问题**：首页回答"有哪些作品"，列表回答"这部作品有什么"，详情回答"这件要不要买"。
2. **作品是导航的第一层**：5 部作品在首页、列表侧栏、面包屑中始终可见。
3. **金额、分类名、状态文案全站同一口径**，全部由后端数据生成，模板不写死。
4. **诚实展示**：没有实现的能力不出现按钮。原型里的"立即购买""到货提醒""销量榜""优惠券""物流轨迹"一律删除。


- **购物车徽标**：本人全部 `cart_item.quantity` 之和（含失效条目），游客显示 `0`；不代表"可结算数量"。

- 顶部条不放任何未实现的承诺（会员、积分、保障计划）。

## 4. 关键页面

> `/works` 作品墙与 `/works/{id}` 作品页是 M02-08 追加的入口：作品墙平铺 5 部作品（封面 + 名称 + 商品数），
> 作品页 = 横幅 + 品类胶囊（单行本 / 周边各品类）+ 该作品商品；两者都只展示 `ON_SALE`，缺图走占位。

### 4.1 首页 `/main`

| 区块 | 内容与规则 |
|---|---|
| 品牌横幅 | 装饰图 + 品牌文案；「开始选购」进 `/category`，不直接下单 |
| 作品入口 | 5 个一级分类，显示作品名 + 英文名 + 商品数 |
| 新品上架 | 上架商品 `created_at DESC, id DESC` 取 3，标题旁「更多新品」进列表并带 `sort=NEWEST` |
| 精选推荐 | 上架商品 `sort_order ASC, id ASC` 取 4，全体一致 |
| 空状态 | 无上架商品 → 「暂无上架商品」+ 去后台添加的说明（仅管理员可见）；分类为空 → 不渲染伪分类 |

两栏允许重复商品；不足时按实际数量显示，不填充假数据。

### 4.2 列表 `/category`

```
┌──────────────┬───────────────────────────────────────────┐
│ 作品分类      │ [全部] [漫画] [周边]        共 18 件  [排序▾] │
│ 星轨列车   18 │ ┌────────┐ ┌────────┐ ┌────────┐          │
│ 雾港侦探   18 │ │ 第1卷   │ │ 第2卷   │ │ 亚克力  │          │
│ 饭团小馆   18 │ │ ¥28.00 │ │ ¥28.00 │ │ ¥89.00 │          │
│ 机械之森   18 │ └────────┘ └────────┘ └────────┘          │
│ 夏夜蝉鸣   18 │              ‹ 1 2 3 ›                    │
└──────────────┴───────────────────────────────────────────┘
```

> 侧栏数量只统计 `ON_SALE`：每部作品 19 件中第 6 卷为 `DRAFT`，故各显示 18；5 部合计 90 = 上架总数（M02-08-01 后的种子口径，见 docs/03 §5.3）。

- 类型按钮与排序在**同一个 GET 表单**里，点「查询」整页刷新。
- 切换任一项 → 回到第 1 页。
- 无结果：显示当前筛选条件 + 「清空筛选」。
- 页码超过末页：空结果 + 「回到第 1 页」。
- 分类不存在：404 提示，不静默换成别的分类。

### 4.3 详情 `/product/{id}`

```
首页 / 星轨列车 / 单行本 / 星轨列车 第1卷
┌──────────────┐  STARLINE · 单行本
│              │  SKU STARLINE-C01
│   封面/相册   │  简介……
│              │  ─────────────────────────
└──────────────┘  ¥28.00      可售库存 12
[▪][▪][▪]        [− 1 ＋] [加入购物车]
                 作品：星轨列车  类型：漫画·单行本  发货：48 小时内
```

- 相册按 `sort_order, id` 升序；无相册则只显示封面；图片缺失用占位图。
- 零库存：按钮禁用 + 「暂时缺货」，后端仍拒绝。
- 游客点「加入购物车」→ 302 登录，登录后回到本页，需**再次点击**才加车。
- 不出现"猜你喜欢""同作品推荐"。

### 4.4 购物车 `/cart`

- 三列：商品（图 + 名称 + 分类 + 状态）、数量、小计；行尾移除。
- 失效条目单独底纹 + 原因（「已下架」/「库存不足，仅剩 n 件」），仍计入徽标，但不参与可结算判断。
- 底部：商品合计 = 应付总额（无运费、无优惠）。
- 有失效条目时「去结算」禁用并提示先处理。
- 空车：插画 + 「去逛逛」。

### 4.5 结算 `/checkout`

- 左：商品清单（只读，来自后端当前数据）。
- 右：收货人 / 电话 / 地址 + 总额 + 「提交订单」。
- 顶部步骤条：购物车 → 确认订单 → 完成。
- 提交失败保留已填收货信息，逐字段提示。
- 车或价格变化 → 整页提示「购物车已变化，请重新确认」，不静默换价。

### 4.6 订单列表 `/orders`

- 状态页签：全部 / 待支付 / 待发货 / 已发货 / 已完成 / 已取消（数量角标如保留，必须查真实数据）。
- 搜索框：「输入完整订单号」，与状态筛选共同生效。
- 卡片：订单号、创建时间、状态徽章、缩略图、总额、操作（去支付 / 取消 / 查看）。
- 空状态按状态区分文案。

### 4.7 订单详情 `/orders/{orderNo}`

- 头部：状态 + 订单号 + 创建时间。
- 商品快照表：图、名、SKU、单价、数量、行金额。
- 收货信息快照（只读）。
- 金额区：待支付显示「应付」，已支付显示「已模拟支付」。
- 时间线：创建 → 支付 → 发货 → 完成，只显示已发生节点。
- 操作：待支付 →「模拟支付」「取消订单」；已发货（P1）→「确认收货」；其余只读。

### 4.8 模拟支付 `/payment/{orderNo}`

- 大字金额 + 「教学模拟支付，不涉及真实资金」声明。
- 两个按钮：「模拟支付成功」「模拟支付失败」，都是 POST。
- 成功后回订单详情；失败回支付页并提示可重试。
- 不出现支付宝/微信/银行卡图标。

### 4.9 管理端

| 页面 | 要点 |
|---|---|
| 登录 | 与用户端同构，文案明确"管理员入口" |
| 控制台 | 只显示当前管理员与四个导航卡片（分类 / 商品 / 订单 / 顾客），**无统计数字** |
| 分类列表 | 按作品折叠（原生 `<details>`，默认收起）；作品名/编码搜索命中时默认展开；作品行显示其下品类数与商品数；删除按钮在有引用时禁用并说明原因 |
| 分类表单 | 新增二级时父分类只读显示；编辑时编码与父分类只读 |
| 商品列表 | 筛选（一级/二级/名称/状态）；行内：上架/下架、补货、编辑 |
| 商品表单 | 编辑时 SKU 只读、库存只读并提示"补货请用补货入口"；底部显示 `version` 隐藏域 |
| 补货弹窗/页 | 只输入"增加数量"，提交后显示新库存 |
| 顾客列表 | 只列 CUSTOMER（管理员不出现），用户名包含 + 状态筛选，按 ID 升序；启停二次确认；重复操作提示当前状态 |
| 订单列表 | 全站、五状态、订单号精确搜索 |
| 订单详情 | 收货信息、明细、MOCK 凭证、发货按钮（仅 PAID） |

## 5. 状态设计

| 状态 | 表现 |
|---|---|
| 空数据 | 有意义的空文案 + 可行动入口（去逛逛 / 清空筛选 / 返回） |
| 校验失败 | 字段旁红字；保留合法输入；密码不回显 |
| 未登录 | 302 登录页；登录后回原页，写操作需用户重新确认 |
| 会话过期 | 同上，购物车与订单数据不丢 |
| 越权 | 404 页（与"不存在"同一页），不显示目标对象是否存在及任何字段 |
| 数据已变化 | 409 提示条「数据已发生变化，请刷新后重试」 |
| 不存在/下架 | 404 页，可返回列表 |
| 技术异常 | 500 页，通用文案 + 返回首页 |

### 6.2 形态语言

- **粗描边 + 硬阴影**：卡片 `border: 3px solid #16130F`，`box-shadow: 5px 5px 0 #16130F`，悬停位移 2px。
- **直角**，不用大圆角（除头像、状态点）。
- **网点纹理**：大面积底色上叠 10% 透明度的圆点网格，呼应漫画网屏。
- 标题用 900 字重、字距 0.02em；金额用衬线数字。

### 6.3 字体与尺寸

| 用途 | 规格 |
|---|---|
| 中文 | `"Noto Sans SC", "Microsoft YaHei", "PingFang SC", sans-serif` |
| 标题 H1 | 40–58px / 900 |
| 区块标题 H2 | 28–30px / 900 |
| 正文 | 14–15px / 1.6 |
| 辅助 | 11–12px，字距 0.16–0.3em |
| 内容宽度 | 1200px（`padding: 0 28px`） |
| 栅格 | 商品 4 列 / 列表页 3 列（侧栏 236px） |

### 6.4 视口

- 验收：Chrome / Edge，**1366×768** 与 **1920×1080** 两档，不出现遮挡关键控件的布局问题。
- 不要求移动端适配；≤900px 只做基本堆叠，不作为验收项。
