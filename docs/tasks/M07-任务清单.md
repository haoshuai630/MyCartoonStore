## 1. 范围

**做**：

- 管理端登录 / 退出 / 控制台，`CARTOON_ADMIN_SESSION` 与用户端完全独立
- `AdminAuthInterceptor`：每次受保护请求重读 `store_user`，`role=ADMIN` 且 `ENABLED` 才放行
- 两级分类：树形列表、新增一级/二级、编辑（只改名称与排序）、删除（有子分类或商品引用则拒绝）
- 商品：列表（一级/二级、名称、状态、分页）、新增（默认 `DRAFT`）、编辑（SKU 与库存只读、`version` 冲突 409）、上下架、增量补货

- 管理端骨架：8 个模板、`admin.css`、错误页、控制台无统计数字
- 用户端身份口径补齐（AC-05/07）：只接受启用 `CUSTOMER`，失败统一文案，受保护请求重查状态

**不做**：

- P1 用户启停、相册维护（M08）
- 确认收货（M08）
- CSRF token（M09 统一加；本期写请求仍是同源表单）
- 销量/统计/报表、图片上传、商品删除、订单金额或状态的人工编辑、后台代取消

- 真实文件上传（封面只填站内路径字符串；`docs/12` 的外链与图片来源字段留到后续）

## 2. 数据与约束

| 表 | 用到的列 | 约束来源 |
|---|---|---|
| `category` | `id`、`code`、`parent_id`、`name`、`sort_order` | `uk_category_code` 全局唯一（库排序规则不区分大小写）；`uk_category_sibling_name(parent_key,name)` 同级同名唯一；`parent_key` 是生成列，**实体不写**；只允许两级 |
| `product` | 全部列 | `uk_product_sku` 唯一且创建后不改；`category_id` 必须指二级；`price > 0` 两位小数；`stock ≥ 0`；`status ∈ {DRAFT, ON_SALE}`；`version` 是所有写操作的乐观锁 |
| `sales_order` | `order_no`、`user_id`、`status`、四个时间、支付三字段 | 状态与时间成组由 CHECK 强制；发货只允许 `PAID → SHIPPED`，`shipped_at` 取首次值 |
| `store_user` | `id`、`username`、`display_name`、`role`、`status` | 管理端只认 `role='ADMIN'` 且 `status='ENABLED'` |

**分类编码规则（Service 校验，不改表）**：`code` 1–32 位 `[A-Z0-9-]`（只接受大写，不做静默大写化）；二级必须以 `-COMIC` 或 `-MERCH` 结尾；`code`、`name` 去首尾空白后写入。

## 4. 接口与语义

> 管理端 `context-path=/admin`，下表路径省略前缀；模板里用 `@{/...}` 由 Thymeleaf 自动补前缀。

### 4.1 登录与控制台

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/login` | 登录页；已登录时 302 `/` |
| POST | `/login` | 只接受启用 `ADMIN`；成功重建会话并 302 `/`；失败 200 回显用户名 + 统一文案 |
| POST | `/logout` | 销毁管理端会话，302 `/login` |
| GET | `/` | 控制台：当前管理员、三个导航入口，无任何统计数字 |

### 4.2 分类

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/categories` | 两级树；一级行显示其下二级数量 |
| GET | `/categories/new` | 新增表单；带 `parentId` 即新增二级（父分类只读显示） |
| POST | `/categories` | 新增；编码/同级同名冲突 409，层级或后缀非法 400 |
| GET | `/categories/{id}/edit` | 编辑表单；编码与父分类只读 |
| POST | `/categories/{id}` | 只改名称与排序；同名 409 |
| POST | `/categories/{id}/delete` | 删除；有子分类或任意商品引用（含 `DRAFT`）409 |

### 4.3 商品

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/products` | 列表：`categoryId`（一级取子树/二级精确）、`keyword`、`status`（`ALL/DRAFT/ON_SALE`）、`page`、`pageSize`；按 `id DESC` |
| GET | `/products/new` | 新增表单；状态固定 `DRAFT`、可填初始库存 |
| POST | `/products` | 新增；SKU 重复 409，字段非法 400，所属分类非二级 400 |
| GET | `/products/{id}/edit` | 编辑表单；SKU 与库存只读，携带 `version` |
| POST | `/products/{id}` | 保存资料；`version` 冲突 409；不改 SKU、库存、状态 |
| POST | `/products/{id}/status` | 上架 / 下架；`version` 冲突 409 |
| POST | `/products/{id}/restock` | 增量补货：`quantity` 1–100000，原子 `stock = stock + ?`，返回最新库存；溢出 409 |

### 4.4 订单

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/orders` | 全站：`orderNo` 精确、`status` 五态 + `ALL`、`page`、`pageSize`（默认 10）；`created_at DESC, id DESC` |
| GET | `/orders/{orderNo}` | 详情：明细快照、收货快照、金额、状态、时间、MOCK 凭证、所属用户（不存在 404） |
| POST | `/orders/{orderNo}/ship` | 仅 `PAID → SHIPPED` 并写首次 `shipped_at`；`PENDING_PAYMENT`/`CANCELLED`/`COMPLETED` 409；重复发货提示"已处理"且不改时间 |

**统一口径**：未登录 302 到管理端登录页（POST 被拦也一样，登录后不重放写请求）；参数错误 400；不存在 404；状态或版本冲突 409；越权访问（非 ADMIN）一律 302 登录页，不进入业务页。

## 6. 设计约定

- **规则在 Service**：分类层级与编码、商品字段与版本、补货溢出、发货状态迁移都写在业务模块；Controller 只做参数绑定、会话判断与跳转。
- **管理端身份**：会话只存 `userId` + `displayName`；`AdminAuthInterceptor` 每个受保护请求按 id 重读 `store_user`，`role=ADMIN` 且 `ENABLED` 才放行，禁用立即生效（docs/02 §6.1）。
- **会话重建**：管理端登录先 `invalidate()` 再新建会话（docs/02 §6.2）；用户端按现状保留，重放留 M09 统一处理。
- **用户端身份口径补齐**：`authenticateCustomer` 只放行启用 `CUSTOMER`；失败统一「账号或密码错误，或账号不可用」（FR-U-01 / AC-05）。
- **跨模块装配放 web 层**：`order` 不依赖 `account`（docs/09 §2.3），订单详情页的"所属用户"由 `AdminOrderController` 调 `AccountService` 批量取，`order` 模块只返回订单与明细。
- **版本冲突统一 409**：商品保存/上下架都用 `UPDATE ... WHERE id=? AND version=?` + `version = version + 1`，影响 0 行即 409「数据已发生变化，请刷新后重试」。
- **补货只做增量**：原子 `UPDATE product SET stock=stock+?, version=version+1 WHERE id=? AND stock <= 2147483647 - ?`，不做"读-改-写"，也不提供"设为指定值"。
- **发货先锁订单行**：`lockByOrderNo` → 判状态 → 写 `shipped_at`；重复发货不改首次时间（与 M06 支付幂等同一口径）。
- **列表分页口径统一**：`PageQuery`（1–50，缺省 10）；商品列表固定 `id DESC`、订单列表 `created_at DESC, id DESC`，SQL 里排序写死，不接受任意字段。
- **页面诚实**：控制台没有统计数字；商品表单不出现删除按钮；库存只读并提示"补货请用补货入口"；分类删除按钮在有引用时禁用并说明原因。
- **错误页同构**：管理端 `error/error.html` 复用用户端的版式，文案取 `BizException` 消息与 HTTP 状态。

## 7. 与设计文档的差异（需要确认）

1. **后台商品列表排序**：docs/04 只规定排序白名单用于用户端；后台未指定，本清单取 `id DESC`（最近录入在前），翻页稳定。
2. **不可编辑字段的回传**：编辑提交里带 `sku`/`stock` 时服务端**忽略**而非报 400，与"编辑页只读"一致；若希望严格拒绝，改成 400。
3. **分类编码大小写**：只接受大写 `[A-Z0-9-]`，不静默转大写（唯一键本身不区分大小写，静默转换会让"看到的"和"存下的"不一致）。
4. **重复发货**：按"已处理"提示并保持首次 `shipped_at`，不返回 409（与 FR-A-06"重复发货提示已处理"一致）。
5. **补货溢出**：`stock + quantity` 超过 `INT` 上限返回 409「库存已达上限」，不当作 500 技术异常。
6. **用户端身份修正纳入本模块**：会改到 M03 已验收的两个断言（禁用文案、`userId=1` 的夹具），改动范围与理由写进 M07-01 汇报；若希望留在 M09，请说明，M07-02 只做管理端拦截。
7. **订单详情的所属用户**：由 web 层装配（`order` 不依赖 `account`），不为此新增模块依赖。
