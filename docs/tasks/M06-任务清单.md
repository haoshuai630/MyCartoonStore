## 1. 范围

**做**：

- `GET /payment/{orderNo}` 支付页：大字金额、教学声明、两个 POST 按钮、返回详情与取消入口
- `POST /payment/{orderNo}/success`、`POST /payment/{orderNo}/failure`
- 支付成功：锁订单 → 校验归属与状态 → 生成凭证 → 置 PAID → **不碰库存**
- 支付失败：不写库、不生成凭证，回支付页提示可重试
- 已 PAID 再支付：幂等，保留首次 `payment_no` 与 `paid_at`
- 订单详情与列表卡片补「去支付」入口（仅待支付）；列表卡片同时补「取消」（M05-05 审阅遗留）
- `/payment/**` 纳入登录拦截（`WebConfig`）

**不做**：

- 真实支付渠道、回调、对账、退款（本实验只做模拟）
- 发货/确认收货（M07 与 M08/P1）
- CSRF token（M09 统一加；当前写请求仍为同源表单）
- 优惠、运费、部分支付、多次支付

## 2. 数据与约束

| 表 | 用到的列 | 说明 |
|---|---|---|
| `sales_order` | `order_no`、`user_id`、`status`、`total_amount`、`payment_method`、`payment_no`、`paid_at`、`created_at` | 支付三件套由 `ck_order_payment_info` 强制成组出现；`uk_order_payment_no` 唯一；`paid_at >= created_at` |
| `sales_order_item` | `product_id`、`quantity`、`line_amount` | **只读**：支付不改明细，用例断言金额与件数不变 |
| `product` | `stock`、`version` | **不改**：支付只改订单状态，用例断言库存与版本不变 |
| `cart_item` | — | **不碰**：支付不回填购物车 |

**凭证规则**：`payment_no = PAY + yyyyMMddHHmmss + 4 位随机数字`（共 21 位，VARCHAR(40) 内），插入前用
`countByPaymentNo` 查重、最多 3 次，数据库唯一键兜底；`payment_method` 固定 `MOCK`；`paid_at` 取统一 `Clock`。

## 4. 接口与语义

| 方法 | 路由 | 行为 |
|---|---|---|
| GET | `/payment/{orderNo}` | 本人待支付订单显示支付页；已支付（含发货/完成）302 跳详情；已取消 409；不存在/他人 404 |
| POST | `/payment/{orderNo}/success` | 成功 → 302 `/orders/{orderNo}`；已支付幂等 → 同样 302，凭证不变；已取消/已发货/已完成 409 |
| POST | `/payment/{orderNo}/failure` | 不写库 → 302 回支付页并提示"支付失败，可重试"；已支付幂等 → 302 详情 |

**状态语义**：

| 当前状态 | 支付成功 | 支付失败 | GET 支付页 |
|---|---|---|---|
| PENDING_PAYMENT | 置 PAID，写三件套 | 无变化，可重试 | 渲染支付页 |
| PAID | 幂等，保留首次凭证与时间 | 无变化 | 302 详情 |
| CANCELLED | 409 不可支付 | 无变化 | 409 |
| SHIPPED / COMPLETED | 409（正常流程不会出现未支付先发货） | 无变化 | 302 详情 |

**错误口径**：不存在与不是本人一律 404（同码同文案，不泄露存在性）；状态不允许一律 409；
未登录由拦截器 302 到登录页并带回跳地址。

## 5. 测试计划（AC-20、AC-24）

| 用例 | 断言 |
|---|---|
| 失败一次 | 状态仍待支付、`payment_no/paid_at/payment_method` 为空、库存与版本不变 |
| 失败后重试成功 | 状态 PAID、`MOCK`、凭证 `PAY` 开头且有值、`paid_at` 非空、库存与版本不变、购物车不变 |
| 成功后再支付 | 状态仍 PAID，`payment_no` 与 `paid_at` 与第一次相同，`updated_at` 之外无副作用 |
| 他人订单支付 | GET 与 POST 均 404，状态与凭证不变 |
| 已取消订单支付 | 409，状态不变、库存不再恢复 |
| 已发货订单支付 | 409，凭证与状态不变 |
| 支付页与入口 | 待支付详情/列表有「去支付」；已支付没有；支付页有"教学模拟支付，不涉及真实资金"声明 |
| 凭证撞号 | 前两次查重命中、第三次成功；连续 3 次命中给 500 可重试文案 |
| AC-24 支付与取消并发 | 两线程同时 POST：只有一种迁移成功；支付赢则 PAID+凭证且库存保持已扣，取消赢则 CANCELLED+库存恢复一次；不出现"已取消却有凭证" |

## 6. 设计约定

- **事务只包 Service**：`paySuccess` / `payFailure` 上 `@Transactional`；Controller 不做状态判断以外的业务。
- **锁订单行**：`lockByOrderNo`（`SELECT ... FOR UPDATE`）先锁再判状态；并发的支付/取消在订单行上排队。
- **幂等不覆盖**：看到 `PAID` 直接返回 `ALREADY_PAID`，不重新生成凭证、不改 `paid_at`。
- **支付不碰库存**：本模块不注入 `ProductMapper`，用例断言 `stock`/`version`/`cart_item` 不变。
- **凭证先在服务端生成**：页面不传金额与单号；金额只取 `total_amount`，下单后改价/下架不影响有效待支付订单。
- **页面诚实**：不出现支付宝/微信/银行卡图标，明确写"教学模拟支付，不涉及真实资金"；入口只对待支付出现。
- **归属与错误码**：沿用 M04/M05 口径——他人与不存在同为 404，状态冲突 409。

## 7. 与设计文档的差异（需要确认）

1. **已支付再支付的表现**：[02 篇 §7.4](../02-概要设计说明书.md)写"幂等提示"，本清单实现为 302 回详情并由一次性提示告知"订单已支付"，不新增错误码，也不在支付页停留。
2. **`docs/04` 的模板名**：接口表里详情页写 `order.html`，实际模板是 `order-detail.html`（M05 已如此），M06 沿用实际文件名，不改文档中的路由。
3. **列表卡片的「取消」**：属 M05-05 审阅遗留（"暂只在详情页"），本模块与支付入口一起补在卡片上，取消后回详情页。

## 8. 风险与约定

| 风险 | 处理 |
|---|---|
| 并发支付同一单 | 订单行锁 + 状态判断；第二个事务看到 PAID 走幂等分支 |
| 支付与取消并发（AC-24） | 同一把订单行锁；先到者迁移，后到者按状态给幂等或 409 |
| 凭证撞号 | 生成前 `countByPaymentNo` 查重，最多 3 次；唯一键兜底 |
| 支付失败被误记为已支付 | 失败分支不写库，用例断言三件套为空 |
| 库存被重复扣 | 支付只改订单状态，完全不触碰 `stock`；用例断言库存不变 |
| CHECK 约束拒绝半套支付信息 | 三件套在同一 `UPDATE` 写入；`updateById` 只会写非空字段 |
| CSRF | M09 统一加，本模块沿用现有同源表单 |
