## 2. 数据与约束

| 对象 | 约束 | 说明 |
|---|---|---|
| Session | 新增键 `csrfToken` | 不落库；有效期随会话（30m）；只存令牌字符串本身 |
| `sales_order` / 其余六表 | 无变更 | 本期不动 DDL 与索引 |
| `product.description` | TEXT，应用层去空白后 ≤2000 | 数据库仍允许 65535 字节，2000 是后台录入上限，防误填与整页渲染过重 |
| `product.cover_image` | VARCHAR(255)，**必须**以 `images/` 开头 | 与 `ImageForm` 的「只接受站内路径」一致；拒绝 `http://`、`//`、`../` |
| 会话 ID | 登录成功前后必须不同 | `changeSessionId()` 轮换；令牌与身份属性随会话迁移，不失效 |
| 证据文件 | `reports/evidence/` | 命名 `m09-ac<编号>-<内容>.<log\|sql\|txt\|md>` |

**业务规则（写进代码，不改表）**：

- CSRF 校验只拦**非安全方法**（`POST/PUT/PATCH/DELETE`）；`GET/HEAD/OPTIONS` 一律放行，且安全请求要**确保**会话里已有令牌
- 令牌比对用恒定时间比较（`MessageDigest.isEqual`），空令牌、空会话一律拒绝，不做「缺失就跳过」的兜底
- 过滤器不处理静态资源（`/css/**`、`/images/**`、`/favicon.ico`），避免为每个静态请求建会话
- 未登录 + 无令牌的写请求：**先 403**（过滤器在拦截器之前），带合法令牌才轮到 302 登录页；口径进 docs/04 §1
- 商品描述：空串存 `NULL`；封面：去空白后判断前缀与长度，不合格 400，文案带字段名

## 4. 接口与语义

### 4.1 CSRF（两端一致）

| 项 | 规则 |
|---|---|
| 令牌生成 | 首次安全请求时生成 UUID，存 `session["csrfToken"]`；同一会话不变 |
| 提交方式 | 表单隐藏域 `_csrf`；`th:action` 的表单统一由 `fragments/csrf.html` 渲染该输入 |
| 校验范围 | `POST/PUT/PATCH/DELETE`；`GET/HEAD/OPTIONS` 不校验 |
| 失败 | 403 + `error/403.html`（「页面已过期或来源不可信，请刷新后重试」），不执行业务、不写库 |
| 与身份的关系 | 过滤器先于 `LoginInterceptor`：无令牌的匿名写请求 403；带合法令牌但未登录的写请求才 302 登录页 |
| 静态资源 | `/css/**`、`/images/**`、`/favicon.ico` 不生成令牌、不建会话 |

### 4.2 用户端登录

| 方法 | 路径 | 变化 |
|---|---|---|
| POST | `/login` | 校验通过后 `changeSessionId()` 再写 `userId` / `displayName`；前后会话 ID 不同，令牌与回跳地址不丢 |

### 4.3 后台商品表单

| 字段 | 规则 | 失败 |
|---|---|---|
| `description` | 可空；去首尾空白；≤2000 字符；空串存 `NULL` | 400「描述不能超过 2000 个字符」 |
| `coverImage` | 必填；去首尾空白；≤255；必须以 `images/` 开头；拒绝 `://`、`//`、`..` | 400「封面必须是站内路径（images/ 开头）」 |

## 6. 设计约定

- **令牌在公共件，注册在 web 层**：`CsrfToken` / `CsrfFilter` 放 `cartoon-common`（只依赖 `spring-web` 与 `jakarta.servlet-api`，二者已是 provided），`FilterRegistrationBean` 放两端 `config`，保持「业务模块不依赖 Web starter」。
- **一处渲染，不逐表单手写**：`fragments/csrf.html` 提供 `hidden` 片段，29 处表单用 `th:replace` 引入；漏写一处就是 403，容易在用例里发现。
- **令牌只存会话，不存 Cookie**：与既有「会话只走 Cookie 跟踪」一致，不做双提交 Cookie，避免两端 Cookie 名冲突与 JS 读取。
- **会话重建用 `changeSessionId()`**：Servlet 3.1+ 的标准做法，与管理端 M07-02 已实现的写法同构；相比 `invalidate()` + 新建会话，令牌与回跳参数不用重新搬运，测试用例也不用重写断言。
- **403 用独立模板**：Spring Boot 的错误视图解析按 `error/403` 找模板，新建 `error/403.html` 才能命中；`error/error.html` 继续服务业务异常。
- **证据以请求/响应 + SQL 为准**：本环境不做浏览器截图，docs/06 §4 允许「页面截图**或**请求 / 数据库结果」；需要视觉核对的部分在验收记录里标注为「需人工看图」。

## 7. 已确认的决定（2026-11-18）

1. **用户端会话重建**：用 `changeSessionId()`（与管理端一致、令牌不丢），同步 docs/02 §6.2 的实现状态说明。
2. **CSRF 令牌的暴露方式**：按 docs/02 §6.3 用 `@ControllerAdvice` + `fragments/csrf.html`；不用 `RequestDataValueProcessor` 自动注入（页面上看不到令牌，评审不直观）。
3. **未登录写请求的优先级**：无令牌一律先 403，带令牌未登录才 302；docs/04 §1 补一句「先校验 CSRF」。
4. **商品描述上限取 2000**：docs/01 FR-A-03 补「≤2000」，docs/03 §2.3 注明应用层上限。
5. **封面只接受站内路径**：`images/` 开头，拒绝 `://`、`//`、`..`；docs/12 的外链方案届时再放宽。
6. **AC-32 执行方式**：`mysqldump` 备份到 `_scratch/` → `DROP DATABASE MyCartoonStore` → 执行 `db/02-schema-with-demo.sql` 取证 → 恢复备份并核对行数。
7. **实验报告格式**：Markdown 一份（`reports/M09-实验报告.md`），不额外导出 Word。
8. **AC-28/AC-32 证据形态**：以 HTTP 请求/响应、SQL 前后对照、两端日志时间戳为准（docs/06 §4 允许），不做浏览器截图。

## 8. 风险与约定

| 风险 | 处理 |
|---|---|
| 给 108 处 POST 补令牌可能漏改，导致既有用例红 | 用 `CsrfTestSupport.csrf()` 统一；先跑 `cartoon-user-web` 与 `cartoon-admin-web`，红了按类逐个补齐；机械改动脚本化后人工抽查 diff |
| 过滤器注册进 MockMvc 后，`LoginInterceptorTest` 的「未登录 302」可能变 403 | 该用例带令牌即可恢复 302；同时新增「无令牌 → 403」的显式用例，把两种口径都固定下来 |
| `sendError(403)` 走到 Boot 错误页，可能命中 Whitelabel | 两端新增 `templates/error/403.html` 并在用例中断言页面文案；启动后手工再验一次 |
| 令牌与会话重建顺序写错，登录后首个页面 403 | 登录用例断言「登录后 GET /main 200 且含新令牌」；提交前跑用户端全量 |
| AC-28 两个实例与测试库争用 | 并发证据用演示库 `MyCartoonStore`；`mvn` 测试用 `MyCartoonStore_test`，两边互不影响；执行前先停掉占用端口的旧构建实例 |
| 现有 8080/8081 实例是 M07 旧构建（控制台仍三入口） | 取证前用 `mvn -pl ... spring-boot:run` 或 `java -jar` 以最新构建重启，日志开头写入构建时间 |
| AC-32 恢复失败导致演示数据丢失 | 备份文件保留在 `_scratch/`，恢复后核对 7 表行数；失败则直接重跑 `02` 重建基线 |
| 描述上限 2000 与种子数据冲突 | 种子描述均短于 2000；用例里显式造 2001 字夹具 |
| 时间 | 18h 偏紧；若超时，优先保 CSRF、会话重建与 AC-31/32 证据，实验报告可拆到下一轮 |
