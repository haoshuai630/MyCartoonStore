## 1. 范围

**做**：

- 后台商品删除（指导书「删除商品（Item）」）：先查订单引用，有引用则拒绝并提示改用下架；无引用时清购物车条目、删相册、删商品
- 后台顾客资料修改（指导书「用户信息查看、修改」）：显示名 / 邮箱 / 电话，只处理 `CUSTOMER`
- 后台密码重置（指导书「密码重置」）：生成一次性临时密码，BCrypt 入库，明文只在一次提示里显示
- 后台订单修改（指导书「修改订单」）：只改收货人 / 电话 / 地址，且只在 `PENDING_PAYMENT`、`PAID`
- 后台订单删除（指导书「删除订单」）：只删 `CANCELLED` 订单，先删明细再删主表；库存不回滚（取消时已恢复）
- 用户端图形验证码（指导书「注册、登录、验证码」）：登录与注册各一处，4 位字符，服务端 PNG，一次性
- 相应页面、用例、汇报与状态同步

**不做**：

- 改表结构（七张表一字不改，全部用现有列）
- 软删除字段、操作审计、订单金额/明细的人工编辑（快照原则不变）
- 邮件/短信验证码、第三方图形验证码服务（不引依赖，JDK 画图）
- 订单状态的人工跳转（发货仍是唯一的状态入口）

## 2. 数据与约束

| 对象 | 约束 | 说明 |
|---|---|---|
| `product` 删除 | 有 `sales_order_item` 引用时拒绝 | 历史订单明细不可悬空；无引用时先删 `product_image`、`cart_item` 再删 `product` |
| `product` 下架 | 仍保留 | 与删除的区别写进界面提示 |
| `store_user` 修改 | 只写 `display_name`/`email`/`phone` | 复用 `ProfileForm` 的列宽校验（50/100/30） |
| `store_user` 重置密码 | 只写 `password_hash` | 随机 12 位（大小写字母 + 数字），BCrypt cost 10 |
| `sales_order` 修改 | 只写 `receiver_name`/`receiver_phone`/`receiver_address` | 仅 `PENDING_PAYMENT`、`PAID`；长度 1–50 / 1–30 / 1–255 |
| `sales_order` 删除 | 仅 `CANCELLED` | 先删 `sales_order_item` 再删主表；不动库存与商品 |
| 验证码 | 会话键 `captchaCode` | 4 位大写字母与数字，忽略大小写比对；校验一次即清除 |

## 4. 接口与语义（管理端省略 `/admin` 前缀）

| 方法 | 路径 | 参数 | 行为 |
|---|---|---|---|
| POST | `/products/{id}/delete` | — | 有订单引用 409；否则清购物车、删相册、删商品，302 回列表 |
| POST | `/users/{id}/profile` | `displayName` `email` `phone` | 只处理 CUSTOMER；非法 400 回列表；成功 302 并提示 |
| POST | `/users/{id}/password-reset` | — | 生成临时密码并落库，302 回列表，临时密码只在一次提示里显示 |
| POST | `/orders/{orderNo}/receiver` | `receiverName` `receiverPhone` `receiverAddress` | 仅待支付/已支付；非法 400、状态不符 409 |
| POST | `/orders/{orderNo}/delete` | — | 仅已取消；先删明细再删主表；其他状态 409 |

用户端：

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/captcha` | 返回 PNG（`no-store`），会话写入 4 位验证码 |
| POST | `/login` | 多一个 `captcha` 参数；不匹配回表单并提示，匹配后按原逻辑登录 |
| POST | `/register` | 同上 |

统一口径：写操作一律 `POST` + PRG；越权与不存在统一 404；状态冲突 409；参数非法 400。

## 6. 口径（直接按此实现，不再逐条确认）

1. **删除商品**：物理删除，但**有订单明细引用时拒绝**——历史订单不能悬空；有购物车引用时先清条目再删（顾客车里的失效条目消失）。
2. **下架与删除并存**：列表同时给「下架」与「删除」，删除按钮的提示里写明"删除后不可恢复，若只是停售请用下架"。
3. **重置密码**：不接受管理员手填新密码，只生成临时密码并在页面显示一次；不记录日志。
4. **订单修改**：只改收货三字段，不改金额、明细、状态；已发货与已完成不可改（快照已随货发出）。
5. **订单删除**：只删已取消订单；不恢复库存（取消时已恢复），不删商品。
6. **验证码**：登录与注册都要；验证码错误时**不暴露**账号是否存在，文案与密码错误区分开（"验证码不正确"）。

## 7. 风险与约定

| 风险 | 处理 |
|---|---|
| 删除商品触发外键失败 | 顺序固定：查订单引用 → 清购物车 → 删相册 → 删商品；删购物车用 `DELETE ... WHERE product_id=?` |
| 删除订单后列表分页错位 | 删除后回第 1 页并提示 |
| 重置密码的明文泄漏 | 只放 `RedirectAttributes` 一次性提示，不进会话与日志 |
| 验证码图片在测试环境不可用 | 图片生成用 JDK `BufferedImage`，测试直接写会话值，不依赖图形 |
| 验证码挡住既有登录用例 | 所有既有登录/注册用例改为先写会话 `captchaCode`；新增 `CaptchaTest` |
| 时间 | 11h 偏紧；优先保 M10-01/02/03，验证码最后 |
