## 1. 范围

**做**：

- 用户端个人资料（FR-U-03）：`/profile` 查看与修改 `display_name`、`email`、`phone`，用户名 / 角色 / 状态不可由本人改
- 用户端修改密码（FR-U-04）：`/password` 校验旧密码与强度规则，成功后销毁当前浏览器会话并回登录页
- 用户端确认收货（FR-O-05）：订单详情对 `SHIPPED` 显示「确认收货」，迁移到 `COMPLETED` 并写首次 `completed_at`，重复提交幂等
- 管理端顾客列表与启停（FR-A-07）：`/admin/users` 只列 `CUSTOMER`，按用户名包含匹配 + 状态筛选 + 分页（`id ASC`），启停前二次确认
- 管理端相册维护（FR-A-07）：`/admin/products/{id}/images` 按商品查看 / 新增 / 编辑 / 删除 `product_image`，删除只删记录
- 入口与文档：页头「个人资料」、订单详情「确认收货」、控制台第 4 张「用户管理」卡片、商品列表行内「相册」；同步 docs/04 §3.1、docs/05 §4.9

**不做**：

- CSRF 同步令牌（M09 统一）、用户端登录重建 Session（M09）
- 头像、图片上传与文件管理（相册只维护记录，图片仍是仓库内 SVG）
- 邮箱 / 手机验证码、找回密码、地址簿、第三方登录
- 管理端修改管理员自己的资料与密码（后台只有登录 / 登出）
- 商品删除、订单金额或状态的人工编辑、订单备注、物流公司与运单号、操作审计
- 邮件 / 短信通知、注册协议勾选

## 2. 数据与约束

| 表 | 用到的列 | 约束来源 |
|---|---|---|
| `store_user` | `id`、`username`、`display_name`、`email`、`phone`、`password_hash`、`role`、`status` | `uk_user_username` 不变；`display_name` 非空 ≤50；`email` ≤100、`phone` ≤30，均可空；`role`/`status` 只能由管理端启停改，本人不可改；密码只存 BCrypt |
| `sales_order` | `status`、`shipped_at`、`completed_at` | CHECK 成组：`COMPLETED` ⇒ `completed_at` 非空；`SHIPPED/COMPLETED` ⇒ `shipped_at` 非空；时间顺序 `completed_at ≥ shipped_at`；确认收货只允许 `SHIPPED → COMPLETED` |
| `product_image` | `id`、`product_id`、`image_path`、`alt_text`、`sort_order` | `image_path` 非空 ≤255；`alt_text` ≤120；`sort_order ≥0`；`fk_image_product` 随商品存在；索引 `(product_id, sort_order, id)` |
| `product` | `cover_image`、`status` | 相册维护**不改** `cover_image`、不递增 `product.version`；无相册时详情页回退封面（现有 `CatalogService` 逻辑） |

**业务规则（Service 校验，不改表）**：

- 资料只写当前会话 `userId` 的那一行，接口不接收目标 id，天然无越权面。
- 改密：旧密码必须匹配；新密码 8–32 字符、UTF-8 ≤72 字节、至少含字母/数字/符号中的两类、不接受空白；新密码不得与旧密码相同；成功后 `session.invalidate()`。
- 确认收货：`lockByOrderNo` → 非本人或不存在 404 → 已 `COMPLETED` 返回"已处理" → 非 `SHIPPED` 409 → 迁移并写首次 `completed_at`（用 `Clock`，测试可固定）。
- 用户启停：只处理 `role='CUSTOMER'`；非 CUSTOMER 或不存在一律 404；重复设置同一状态提示当前状态，不报错。
- 相册排序：`sort_order ASC, id ASC`；新增缺省 `sort_order=0`；编辑不改 `product_id`。

## 4. 接口与语义

### 4.1 用户端（`:8080`，受保护路径经 `LoginInterceptor`）

| 方法 | 路径 | 参数 | 行为 |
|---|---|---|---|
| GET | `/profile` | — | 资料页：回显当前 `display_name`、`email`、`phone` 与用户名（只读） |
| POST | `/profile` | `displayName` `email` `phone` | 保存；成功 302 `/profile` + 一次性提示；非法 200 回表单并逐字段提示 |
| GET | `/password` | — | 改密页：旧密码、新密码、确认新密码 |
| POST | `/password` | `oldPassword` `newPassword` `confirmPassword` | 校验全部通过才写库；成功销毁当前会话并 302 `/login`；失败 200 回表单 |
| POST | `/orders/{orderNo}/complete` | — | 仅本人 `SHIPPED` 订单；成功 302 详情；重复提交提示"已处理"；非 `SHIPPED` 409；非本人 404 |

### 4.2 管理端（`:8081`，下表省略 `/admin` 前缀）

| 方法 | 路径 | 参数 | 行为 |
|---|---|---|---|
| GET | `/users` | `keyword` `status` `page` `pageSize` | 只列 `CUSTOMER`；`keyword` 用户名包含匹配（去空白、≤50）；`status ∈ {ALL, ENABLED, DISABLED}`；`id ASC`；缺省每页 10 |
| POST | `/users/{id}/status` | `status`（`ENABLED`/`DISABLED`） | 启停；非 CUSTOMER 或不存在 404；重复设置提示当前状态 |
| GET | `/products/{id}/images` | — | 相册列表 + 新增表单；商品不存在 404 |
| POST | `/products/{id}/images` | `imagePath` `altText` `sortOrder` | 新增图片记录；字段非法 400 |
| POST | `/products/{id}/images/{imageId}` | `imagePath` `altText` `sortOrder` | 编辑；图片不属于该商品 404 |
| POST | `/products/{id}/images/{imageId}/delete` | — | 删除记录（不删文件、不改 `cover_image`） |

**统一口径**：未登录 302 本端登录页（登录后不重放写请求）；参数错误 400；不存在或越权 404；状态或版本冲突 409；写操作一律 `POST` + 重定向（PRG）。
用户端表单错误沿用登录 / 注册惯例（200 回表单）；管理端表单沿用 M07 惯例（400/409 + 回表单）。

## 6. 设计约定

- **规则在 Service**：资料字段校验、密码强度、启停状态判断、图片字段校验都写在业务模块；Controller 只做参数绑定、会话判断与跳转。
- **资料页无目标 id**：只改当前会话用户，路由不带 `{id}`，从入口上消除越权面（与 FR-U-02 一致）。
- **改密只销毁当前会话**：FR-U-04 明确"其他浏览器已有会话继续有效"，因此不做全局会话吊销、不写额外表。
- **确认收货与取消同构**：`lockByOrderNo` → 归属 404 → 幂等分支 → 非法状态 409 → 迁移写时间；重复提交与 M06/M07 的幂等口径一致。
- **禁用即时生效复用 M07-01**：`LoginInterceptor` 每请求重读账号，本模块不改拦截逻辑，只改 `status`。
- **相册与商品资料分开写**：相册增删改不递增 `product.version`、不碰 `cover_image`；商品的版本仍只由资料 / 上下架 / 补货 / 下单扣减维护。
- **控制台从三入口变四入口**：新增「用户管理」卡片；相册从商品列表行内进入，不再单独占卡片。
- **页面诚实**：不出现头像、上传按钮、邮件通知、导出等未实现入口。

## 7. 与设计文档的差异（需要确认）

1. **个人资料入口位置**：放在页头身份区（与「退出」并列），不占用顶部导航五栏——避免改 M03 已验收的导航结构；若希望进导航请说明。
2. **控制台四入口**：docs/04 §3.1 与 docs/05 §4.9 现写"三个入口"，本模块改为四个卡片并在同任务内同步文档。
3. **邮箱 / 手机只校验长度**：FR-U-03 只给上限、未要求格式；不做过严格式校验，避免教学假邮箱被拦。
4. **注册 displayName 顺带补校验**：当前只有模板 `maxlength=50`，直发 POST 超长会落到数据库报 500；M08-01 复用同一校验修掉。若不想动 M03 已验收代码，可拆到 M09。
5. **相册 `image_path` 只接受站内路径**：与 `product.cover_image` 一致；外链与图片来源字段留到 docs/12。
6. **重复收货提示文案**：计划「该订单已完成，无需重复操作」（与取消的"无需重复操作"对齐）；如需沿用"已处理"请说明。
