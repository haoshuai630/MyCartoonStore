# M05 任务清单 · 订单

> 目标：从购物车进入结算确认，一次事务生成订单、明细并扣库存、清空已结算条目；
> 能查本人订单列表与详情；待支付订单可取消并恢复库存。

## 范围

| 能做 | 不做（留给后续） |
|---|---|
| 结算确认页 `/checkout`：商品清单、收货信息、总额 | 模拟支付（M06） |
| 结算快照（Session）与"车/价已变"409 重新确认 | 确认收货（M08，P1） |
| 原子下单：订单 + 明细 + 扣库存 + 删结算条目 | 后台发货（M07） |
| 订单列表 `/orders`：状态页签、完整单号搜索、分页 | 地址簿、运费、优惠、发票 |
| 订单详情 `/orders/{orderNo}`：明细快照、时间线、应付款 | 真实支付渠道、物流轨迹 |
| 取消待支付订单 + 库存恢复（幂等） | CSRF（M09 统一做） |
| 归属隔离：他人订单统一 404 | 按商品名搜索订单 |

## 数据

| 表 | 用到的列 | 说明 |
|---|---|---|
| `sales_order` | `order_no`、`user_id`、`status`、`total_amount`、收货三字段、支付/取消/发货/完成时间 | 状态与时间字段成组，由 CHECK 强制 |
| `sales_order_item` | `sku_snapshot`、`product_name_snapshot`、`cover_image_snapshot`、`unit_price`、`quantity`、`line_amount` | 下单时快照，之后商品改名改价不影响历史 |
| `cart_item` | `id`、`product_id`、`quantity`、`version` | 结算依据；下单成功后删除本次条目 |
| `product` | `id`、`price`、`stock`、`status`、`version` | 下单扣减、取消恢复，均维护 `version` |

订单号规则（[03 篇 §3](../03-数据库设计说明书.md)）：`CO` + `yyyyMMddHHmmss` + 4 位随机数字，
插入前查重、冲突最多重试 3 次；**禁止"最大 ID + 1"**。

## 验收口径（AC-12～17、18、19、21～23、30）

| 用例 | 断言 |
|---|---|
| AC-12 收货字段 | 空、全空白、超长（>50 / >30 / >255）逐字段拒绝；金额只由后端算，篡改隐藏价格字段无效；失败不产生订单 |
| AC-13 确认已过期 | 确认后改价 / 改车 / 加车 → 提交 409「购物车或价格已变化，请重新确认」，不静默按新价成交、不误删新增条目 |
| AC-14 正常下单 | 2 件 + 1 件 → 1 主表 2 明细；总额 = 两行金额之和；库存分别 −2、−1 且 `version` +1；本次车条目删除；跳转订单详情 |
| AC-15 部分不可用 | 一件库存不足或下架 → 无订单、无明细、库存全不变、车保留 |
| AC-16 中途异常 | 写订单后 / 扣首个库存后 / 删车前抛异常 → 订单、明细、库存、版本、车全部回滚 |
| AC-17 并发 | 同用户同一车并发提交两次，只成交一单；旧版本改车被拒 |
| AC-18 归属 | 他人订单详情 / 取消 → 统一 404（与不存在同码同文案），订单与库存不变 |
| AC-19 快照 | 下单后改商品名/价/封面/下架 → 历史明细与金额不变 |
| AC-21 取消 | 两件明细取消 → 两件库存各恢复一次、状态 `CANCELLED`、`cancelled_at` 非空、版本正确；重复取消提示"已处理"，库存不再增加；车不回填 |
| AC-22 下架后取消 | 库存恢复，商品仍 `DRAFT`；已取消不能支付/发货 |
| AC-23 取消中途异常 | 恢复第一件库存后抛异常 → 订单仍 `PENDING_PAYMENT`，库存与版本回到取消前 |
| AC-30 查询 | 五种状态 + 完整订单号组合筛选，只显示本人；条件在翻页时保留；非法状态/页参数 400 |

## 设计约定

- **快照只作确认凭据**：Session 存 `userId`、条目 `[cartItemId, productId, quantity, cartVersion, price]`、`totalAmount`；打开确认页不锁价、不占库存。
- **下单以数据库为准**：重新读车并与快照逐项比对（条目集合、数量、版本、价格），不一致一律 409，不静默换价。
- **事务只包 Service**：`placeOrder` / `cancel` 上 `@Transactional`；Controller 不做金额、状态或库存判断。
- **锁顺序**：`cart_item` 行锁（`SELECT ... FOR UPDATE`）→ `product` 按 id 升序 `FOR UPDATE`（复用 `lockByIds`）→ 写订单 → 扣库存（`deductStock` 影响 0 行即失败）→ 删本条条目。
- **"同一车只成交一次"的落点**：删除条目必须返回与核对条目数相同的行数，否则抛异常整体回滚——第二个并发事务删到 0 行，直接回滚。
- **金额口径**：`total_amount` = 明细 `line_amount` 之和；每行 `line_amount = unit_price × quantity`，由数据库 CHECK 兜底；无运费、无优惠、无税。
- **订单号**：`CO` + 时间戳 + 4 位随机数，插入前查重、最多重试 3 次；不用 ID 推导。
- **取消**：先 `lockByOrderNo` 订单行 → 校验归属与 `PENDING_PAYMENT` → 逐条恢复库存（`version` +1）→ 置 `CANCELLED` 与 `cancelled_at`；重复取消不重复加库存。
- **归属**：所有按订单号的操作先查 `user_id`，不是本人与不存在统一 404（M04 已确立的口径）。
- **页面诚实**："模拟支付"按钮只在 M06 接上后出现；M05 的详情页对待支付订单只提供"取消订单"，不放假入口。

## 与设计文档的差异（需要你确认）

1. **不锁 `store_user` 行**：[02 篇 §7.3](../02-概要设计说明书.md)写"先 `SELECT store_user ... FOR UPDATE`"，但 [09 篇 §2.3](../09-模块划分与开发流程.md)规定 `order` 只依赖 `cart`/`catalog`，不依赖 `account`。
   本清单改为：由 `cart` 模块提供"锁本人车行"的读方法，下单以**删车条目数**作为串行化点。效果相同（同车只成交一次），且不破坏模块依赖。
2. **AC-16 的异常注入**：不改生产代码加钩子，测试里用 `@MockitoSpyBean` 让 `CartService` 在"删车"这一步抛异常——仍是从真实业务入口进入事务。

## 风险

| 风险 | 处理 |
|---|---|
| 并发用例不稳定（线程、连接池、锁等待） | 用 `CountDownLatch` 两个线程 + 两个独立事务；超时与断言写成"恰好一单成功" |
| 订单号随机冲突 | 查重 + 最大 3 次重试，失败给 500 并记录 |
| 删车条目数校验依赖快照条目集合 | 快照与重新读取都按 `cartItemId` 排序后比对，避免顺序差异 |
| 取消恢复库存与 M07 补货并发 | 统一 `version` 乐观更新；M07 做补货时再补 AC-28 用例 |
| 改 `CartService` 会影响已验收的 M04 | M05-03 完成后跑全量回归，M04 的 124 个用例必须全绿 |
| 长地址/特殊字符 | 校验长度并 `th:text` 转义；CSRF 仍留 M09 |
| `@MockitoSpyBean` 在 Boot 4 的可用性 | 先做一个最小验证；不可用则改为在测试中重写 `CartService` 的删除方法（子类） |
