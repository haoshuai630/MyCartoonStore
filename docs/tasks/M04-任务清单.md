# M04 任务清单 · 购物车

> 目标：登录用户能把商品加入购物车、改数量、移除，购物车跨会话/重启保留；页头徽标显示真实件数；
> 失效条目保留并说明原因，且拦住"去结算"。

## 范围

| 能做 | 不做（留给后续模块） |
|---|---|
| 加入购物车（同商品累加、库存校验） | 结算确认与下单（M05） |
| 改数量（1–99、库存校验、`version` 冲突检测） | 勾选结算、优惠券、运费（本项目不做） |
| 移除单条 | 购物车合并（未登录车不存在，登录才写库） |
| 购物车页：三列、行小计、合计、空车状态 | 收藏夹、稍后再买 |
| 失效条目（下架 / 库存不足）提示 + 禁止结算 | 自动删除失效条目 |
| 页头徽标 = 全部条目 `quantity` 之和（含失效） | 徽标 AJAX 局部刷新（整页渲染即可） |
| 游客加车 → 302 登录 → 回跳本页 | 登录后自动补加（按 05 篇：需再次点击） |

## 数据

只用 `cart_item` 与 `product` 的只读字段：

| 表 | 用到的列 | 说明 |
|---|---|---|
| `cart_item` | `user_id`、`product_id`、`quantity`、`version` | 同用户同商品唯一（`uk_cart_user_product`）；`quantity` 1–99 由 CHECK 兜底 |
| `product` | `id`、`name`、`cover_image`、`price`、`stock`、`status` | 价格不存购物车，页面每次取当前值 |

种子数据：`alice` 6 条（其中 1 条下架、1 条库存不足）、`bob` 4 条全部可用，正好覆盖失效与正常两种情况。

## 验收口径（对应 AC-08～11）

| 用例 | 断言 |
|---|---|
| 同商品重复加入 | 只有一条记录，数量为两次之和 |
| 数量 0 / 负数 / 小数 / 100 | 400 或表单提示，**不写库**，原条目不变 |
| 累加后超过库存 | 拒绝，提示可购买数量，原数量不变 |
| 小计与合计 | 按当前价格重算，等于各行小计之和；金额两位小数 |
| 数量上限 99 / 种类上限 20 | 拒绝并提示，不产生第 21 条 |
| 退出后重新登录 | 同一账号仍看到原车；`bob` 看不到 `alice` 的条目 |
| 跨账号改量 / 移除 | 403，目标条目数量不变 |
| 旧 `version` 提交 | 409，提示刷新，不覆盖新数量 |
| 失效条目 | 下架显示"已下架"、库存不足显示"仅剩 n 件"，仍计入徽标，无法结算 |
| 页头徽标 | 等于全部条目数量之和；游客为 0 |

## 设计约定

- 规则只在 `CartService`：Controller 只做「会话取 userId → 调服务 → 渲染/重定向」，不判断库存、不拼金额。
- 加车与改量都校验**累加后**的值，不只校验本次输入（FR-C-01 §2）。
- 归属校验放在 SQL 的 `WHERE user_id = ?` 里：查不到与不是本人统一按 403/404 处理，不先查再比对。
- 数量修改与移除都带旧 `version`，`UPDATE ... WHERE id=? AND user_id=? AND version=?` 影响 0 行即冲突（409）。
- 加车的并发兜底用唯一键 `uk_cart_user_product`：重复插入冲突后按"已存在则累加"重试一次，不向用户报 500。
- 失效判定在查询时计算（`status <> 'ON_SALE'` 或 `quantity > stock`），不落库、不后台清洗。
- 购物车页金额用 `MoneyUtils` 计算，模板只输出格式化后的字符串，不做乘法。
- 401/403/409 统一由 `GlobalExceptionHandler` 按 `ErrorCode.status()` 输出（M04 顺带修正目前一律转 400 的问题）。
