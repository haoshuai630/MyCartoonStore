## 任务详情

### M01-01 结构脚本本地化

- **目标**：`01-schema.sql` 库名改为 `MyCartoonStore`，七表 DDL 与课程基线**一字不差**，只动库名与注释。
- **产出**：`db/01-schema.sql`、`db/README.md`
- **验收**：
  1. 空库执行无错误；
  2. `SHOW TABLES` 恰好 7 张；
  3. 与 `E:\Software\QQ\01-schema.sql` 做 diff，差异只出现在 `CREATE DATABASE` / `USE` / 注释行；
  4. 表注释与字段注释按漫画业务微调，但列名、类型、CHECK、索引、外键完全不动。
- **依赖**：无
- **注意**：`parent_key` 是生成列，实体层不许写入。

### M01-02 种子：账号 + 分类 + 商品

- **目标**：4 个账号、15 个分类、60 个商品，一次性写进 `02-schema-with-demo.sql`。
- **产出**：`db/02-schema-with-demo.sql`（表结构 + 账号 + 分类 + 商品）
- **规则**：
  - 账号：`alice` / `bob` / `carol`(DISABLED) / `admin`，明文 `Cartoon123!`，BCrypt cost=10，各自独立盐；
  - 分类：5 个一级（作品）+ 10 个二级（`-COMIC` / `-MERCH`）；
  - 商品：每部作品 6 卷（`{IP}-C01..C06`）+ 6 件周边（`{IP}-M01..M06`）；
  - 6 个 `DRAFT`：五部作品第 6 卷 + `STARLINE-M06`；
  - 3 个售罄（`stock=0`）：`STARLINE-M01`、`MISTPORT-C03`、`CICADA-M02`；
  - 2 个库存 1：`STARLINE-C02`、`ONIGIRI-M01`。
- **验收**：空库执行后 `SELECT COUNT(*)` 得 4 / 15 / 60；`SELECT status, COUNT(*) FROM product GROUP BY status` 得 54 / 6；上述 5 个边界 SKU 的库存与状态逐个核对。
- **依赖**：M01-01

### M01-03 种子：相册 100 条

- **目标**：`product_image` 恰好 100 条，覆盖"有 3 张 / 有 2 张 / 无相册"三种详情页场景。
- **产出**：`02-schema-with-demo.sql` 追加相册段
- **规则**：20 个商品各 3 张、20 个商品各 2 张、20 个商品无相册；路径 `images/products/{sku}/{n}.svg`。
- **验收**：`SELECT COUNT(*) FROM product_image` = 100；`SELECT COUNT(*) FROM product p WHERE NOT EXISTS (SELECT 1 FROM product_image i WHERE i.product_id=p.id)` = 20。
- **依赖**：M01-02

### M01-04 种子：购物车 + 订单 + 明细

- **目标**：10 条购物车、10 张订单、20 条明细，含五状态与 6 张 MOCK 支付。
- **产出**：`02-schema-with-demo.sql` 追加交易段
- **规则**：
  - `alice` 6 条车（其中 2 条失效）、`bob` 4 条；
  - 订单号 `DEMO-202611-0001..0010`，两人各 5 张，五状态各 2 张；
  - `PAID`/`SHIPPED`/`COMPLETED` 共 6 张带 `MOCK` 凭证与 `paid_at`；
  - 时间以导入时刻为基准，满足 CHECK 的时间顺序；
  - **净扣库存**：只对未取消订单扣减，取消订单视为已恢复。
- **验收**：行数 10/10/20；状态分布正确；每张订单的 `total_amount` = 明细 `line_amount` 之和；对 3 个商品核对种子前后库存差 = 该商品未取消订单数量之和。
- **依赖**：M01-02

### M01-05 初始化核对与说明

- **目标**：把"怎么初始化、怎么核对"写清楚，避免别人拿到仓库不知道怎么跑。
- **产出**：`db/README.md`、一段可复制的核对 SQL
- **验收**：在全新空库上按 README 执行一次，得到 4/15/60/100/10/10/20；README 中的命令可直接粘贴运行。
- **依赖**：M01-04

### M01-06 七表实体

- **目标**：7 个实体类，字段与列一一对应。
- **产出**：`cartoon-account`、`cartoon-catalog`、`cartoon-cart`、`cartoon-order` 下的 `entity/*.java`
- **规则**：`@TableName` 显式表名、`@TableId(type=AUTO)`；只映射列，不写业务方法；`parent_key` 不映射（或只读）。
- **验收**：编译通过；每个实体字段数与 `information_schema.columns` 一致（`parent_key` 除外）。
- **依赖**：M01-01

### M01-07 七个 Mapper + 自定义查询

- **目标**：继承 `BaseMapper`，补上业务必需的自定义 SQL。
- **产出**：`mapper/*.java`
- **自定义查询清单**：
  1. 商品列表分页（分类 + 类型 + 关键字 + 排序，4 种排序白名单）；
  2. 首页新品 3 / 精选 4；
  3. 购物车按用户联表查当前价格与库存；
  4. 商品行锁 `SELECT ... FOR UPDATE`（按 ID 升序）；
  5. 用户行锁；
  6. 订单行锁；
  7. 乐观更新：`UPDATE product SET stock=stock-?, version=version+1 WHERE id=? AND stock>=?`；
  8. 订单号 / 支付凭证查重。
- **验收**：每个自定义方法都有对应 SQL 且能执行；禁止 `SELECT *` 与字符串拼接排序字段。
- **依赖**：M01-06

### M01-08 测试基座

- **目标**：集成测试能连真实 MySQL 测试库，且不污染演示库。
- **产出**：`cartoon-test-support`（`TestDatabase`、建库/清库工具）、`application-test.yaml`
- **验收**：`mvn -pl cartoon-catalog test` 能启动 Spring 上下文并连上 `MyCartoonStore_test`。
- **依赖**：M01-07

### M01-09 集成测试（≥8 例）

- **目标**：用真实数据库证明约束与并发行为。
- **用例清单**：
  1. 分类二级必须挂一级（Service 层校验，DB 外键不拦）；
  2. 商品 SKU 唯一冲突；
  3. `product.price <= 0` 被 CHECK 拒绝；
  4. `cart_item` 同用户同商品唯一；
  5. `sales_order_item.line_amount = unit_price * quantity` 被 CHECK 拒绝；
  6. 删除有子分类的分类被外键 RESTRICT 拒绝；
  7. 乐观更新：旧 `version` 更新影响 0 行；
  8. 扣库存：`stock` 不足时影响 0 行；
  9. 订单状态与 `paid_at` 组合违反 CHECK。
- **验收**：9 个用例全绿；测试库在用例前重建。
- **依赖**：M01-08
