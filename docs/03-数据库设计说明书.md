# 03 · 数据库设计说明书

> **原则：七张表的结构、字段名、约束、索引一律沿用课程 `01-schema.sql`，不改一个字符。**
> 本项目只做两件事：① 库名换成 `MyCartoonStore`；② 重写 `02` 的种子数据（分类、商品、图片、订单）为漫画业务。

---

## 1. 逻辑模型

```
store_user ──owns──▶ cart_item ◀──refers── product ◀──belongs── category
     │                                        ▲                    │
     │                                        │                parent_of
     └──places──▶ sales_order ──contains──▶ sales_order_item     （自关联，固定两级）
                        │                          │
                        └── 收货快照、支付信息       └── 商品快照
```

- `category` 自关联，但**业务上固定两级**；`parent_id IS NULL` 为一级，二级必须指向一级。
- 商品只能挂二级；分类不可删除的条件是"有子分类或有商品引用"。
- 订单明细保存成交快照，商品后续改名/改价/下架都不回写。

## 2. 表结构字典

### 2.1 `store_user` 账号

| 字段 | 类型 | 空 | 默认 | 约束/说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | AUTO_INCREMENT | 主键，Java `Long` |
| `username` | VARCHAR(50) | N | | 唯一 `uk_user_username`，创建后不改，不区分大小写 |
| `password_hash` | VARCHAR(255) | N | | BCrypt，禁止明文 |
| `display_name` | VARCHAR(50) | N | | 显示名 |
| `role` | VARCHAR(16) ascii | N | | `CUSTOMER` / `ADMIN` |
| `status` | VARCHAR(16) ascii | N | `ENABLED` | `ENABLED` / `DISABLED` |
| `email` | VARCHAR(100) | Y | | |
| `phone` | VARCHAR(30) | Y | | |
| `created_at` / `updated_at` | DATETIME | N | `CURRENT_TIMESTAMP` | `updated_at` 自动更新 |

CHECK：`username`/`password_hash`/`display_name` 去空白后长度 > 0；`role`、`status` 枚举内。

### 2.2 `category` 两级分类

| 字段 | 类型 | 空 | 默认 | 约束/说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | AUTO_INCREMENT | |
| `code` | VARCHAR(32) | N | | 全局唯一 `uk_category_code`，创建后不改 |
| `parent_id` | BIGINT | Y | | 一级为空；二级指向一级；FK 自引用 `RESTRICT` |
| `parent_key` | BIGINT | N | 生成列 | `COALESCE(parent_id,0)` STORED，**实体不要写它** |
| `name` | VARCHAR(50) | N | | 同级唯一 `uk_category_sibling_name(parent_key,name)` |
| `sort_order` | INT | N | 0 | ≥0 |
| `created_at` / `updated_at` | DATETIME | N | | |

索引：`idx_category_parent_sort(parent_id, sort_order, id)`。

**本项目追加的业务约定（Service 校验，不改表）**

1. 二级分类的 `code` 必须以 `-COMIC` 或 `-MERCH` 结尾——这是"商品类型"的唯一来源。
2. 只允许两级：新增二级时父必须是一级；禁止把二级设为父；禁止自引用与循环。
3. `code`、`name` 去首尾空白后写入。

### 2.3 `product` 商品（一商品一 SKU）

| 字段 | 类型 | 空 | 默认 | 约束/说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | AUTO_INCREMENT | 页面定位用 ID，SKU 只展示 |
| `sku` | VARCHAR(40) | N | | 唯一 `uk_product_sku`，创建后不改 |
| `category_id` | BIGINT | N | | 必须是二级分类；FK `RESTRICT` |
| `name` | VARCHAR(120) | N | | |
| `summary` | VARCHAR(500) | Y | | 列表/详情简介 |
| `description` | TEXT | Y | | 纯文本，模板转义 |
| `cover_image` | VARCHAR(255) | N | `images/logo.png` | 站内相对路径 |
| `price` | DECIMAL(12,2) | N | | > 0 |
| `stock` | INT | N | 0 | ≥ 0，可销售库存 |
| `status` | VARCHAR(16) ascii | N | `DRAFT` | `DRAFT` / `ON_SALE` |
| `sort_order` | INT | N | 0 | 越小越靠前 |
| `version` | BIGINT | N | 0 | 所有写操作显式 +1 |
| `created_at` / `updated_at` | DATETIME | N | | |

索引：`idx_product_category_status_sort`、`idx_product_status_sort`。

### 2.4 `product_image` 相册

| 字段 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | AUTO_INCREMENT | |
| `product_id` | BIGINT | N | | FK `RESTRICT` |
| `image_path` | VARCHAR(255) | N | | 站内路径 |
| `alt_text` | VARCHAR(120) | Y | | |
| `sort_order` | INT | N | 0 | ≥0，详情按 `sort_order, id` 升序 |

相册不替代 `product.cover_image`；无相册时详情回退封面。

### 2.5 `cart_item` 购物车

| 字段 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | AUTO_INCREMENT | |
| `user_id` | BIGINT | N | | FK `RESTRICT` |
| `product_id` | BIGINT | N | | FK `RESTRICT` |
| `quantity` | INT | N | 1 | 1–99 |
| `version` | BIGINT | N | 0 | 数量修改时 +1 |
| `created_at` / `updated_at` | DATETIME | N | | |

唯一键 `uk_cart_user_product(user_id, product_id)`：同用户同商品只有一条。
**不存价格、不占库存**；每车最多 20 种由 Service 校验。

### 2.6 `sales_order` 订单主表

| 字段 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | AUTO_INCREMENT | |
| `order_no` | VARCHAR(40) | N | | 唯一，服务端生成 |
| `user_id` | BIGINT | N | | FK `RESTRICT` |
| `status` | VARCHAR(16) ascii | N | `PENDING_PAYMENT` | 五状态 |
| `total_amount` | DECIMAL(12,2) | N | | > 0，= Σ 明细行金额 |
| `receiver_name` | VARCHAR(50) | N | | 下单时快照 |
| `receiver_phone` | VARCHAR(30) | N | | |
| `receiver_address` | VARCHAR(255) | N | | |
| `payment_method` | VARCHAR(16) ascii | Y | | 成功固定 `MOCK` |
| `payment_no` | VARCHAR(40) | Y | | 唯一，可空 |
| `paid_at` / `cancelled_at` / `shipped_at` / `completed_at` | DATETIME | Y | | 与状态成组 |
| `created_at` / `updated_at` | DATETIME | N | | |

CHECK 组合规则（数据库已强制）：

- `PENDING_PAYMENT` / `CANCELLED`：支付三字段全空。
- `PAID` / `SHIPPED` / `COMPLETED`：`payment_method='MOCK'`、`payment_no` 非空、`paid_at` 非空。
- `CANCELLED` ⇔ `cancelled_at` 非空；`SHIPPED`/`COMPLETED` ⇔ `shipped_at` 非空；`COMPLETED` ⇔ `completed_at` 非空。
- 时间顺序：`paid_at ≥ created_at`、`shipped_at ≥ paid_at`、`completed_at ≥ shipped_at`。

索引：`idx_order_user_created`、`idx_order_status_created`。

### 2.7 `sales_order_item` 订单明细

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| `id` | BIGINT | N | 主键 |
| `order_id` | BIGINT | N | FK `RESTRICT` |
| `product_id` | BIGINT | N | FK `RESTRICT` |
| `sku_snapshot` | VARCHAR(40) | N | |
| `product_name_snapshot` | VARCHAR(120) | N | |
| `cover_image_snapshot` | VARCHAR(255) | N | |
| `unit_price` | DECIMAL(12,2) | N | > 0 |
| `quantity` | INT | N | 1–99 |
| `line_amount` | DECIMAL(12,2) | N | `= unit_price * quantity`（CHECK 强制） |

唯一键 `uk_order_item_product(order_id, product_id)`：同一订单同商品只有一条。

## 3. 订单号与凭证

| 项 | 规则 | 示例 |
|---|---|---|
| 订单号 | `CO` + `yyyyMMdd` + `HHmmss` + 4 位随机数字 | `CO202611141030124817` |
| 支付凭证 | `PAY` + `yyyyMMddHHmmss` + 6 位随机数字 | `PAY20261114103107582913` |

- 服务端生成，插入前查重，冲突重试最多 3 次；**禁止用"最大 ID + 1"**。
- `payment_no` 在同一事务内生成并写入，唯一索引兜底。

## 4. 索引与查询对照

| 查询 | 用法 |
|---|---|
| 首页新品 | `product(status, created_at DESC, id DESC)` 取 3 |
| 首页精选 | `product(status, sort_order, id)` 取 4 |
| 列表按分类 + 排序 | `idx_product_category_status_sort`，`status='ON_SALE'` |
| 列表按名称搜索 | `name LIKE '%kw%'`（教学规模可接受；不做全文索引） |
| 分类树 | `idx_category_parent_sort` |
| 本人订单 | `idx_order_user_created`，`status` 可选 |
| 后台订单 | `idx_order_status_created` |
| 购物车 | `uk_cart_user_product` 覆盖 |

## 7. 初始化与恢复

```bash
# 1) 建库 + 建表 + 种子（二选一，绝不依次执行）
mysql -u root -p < src/main/resources/database/02-schema-with-demo.sql
#    或只要结构
mysql -u root -p < src/main/resources/database/01-schema.sql

# 2) 核对
mysql -u root -p -e "USE MyCartoonStore;
  SELECT (SELECT COUNT(*) FROM store_user) u,(SELECT COUNT(*) FROM category) c,
         (SELECT COUNT(*) FROM product) p,(SELECT COUNT(*) FROM product_image) pi,
         (SELECT COUNT(*) FROM cart_item) ci,(SELECT COUNT(*) FROM sales_order) o,
         (SELECT COUNT(*) FROM sales_order_item) oi;"
# 期望：4 15 60 100 10 10 20
```

约束：

- **只初始化一次**；应用启动不得自动建表或灌数据（`spring.sql.init.mode=never`）。
- 已有同名表时脚本会报错，不要用 `mysql --force` 跳过。
- 恢复演示数据必须显式说明环境与外键删除顺序，不能靠应用清库。
