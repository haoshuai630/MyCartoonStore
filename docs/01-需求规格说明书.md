## 1. 背景与目标

### 1.1 背景

课程提供的 MyPetStore 是一个宠物商城教学项目，PRD 把功能、规则、验收写得非常细。实验指导书明确允许"采用和课程不一样的业务和设计"。本项目把业务域平移为**原创漫画及官方周边**，但保留 PRD 的全部业务机制——因为机制才是实验要考的东西（会话、归属校验、持久化购物车、事务、状态机、并发、乐观锁）。

### 1.2 目标

| 目标 | 可检查的成功标准 |
|---|---|
| 商品信息一致 | 首页、列表、详情、购物车、订单对应同一数据库记录；价格与状态以库为准 |
| 购物车可恢复 | 退出、会话失效、重启后重新登录，仍能查到原购物车；跨账号不串数据 |
| 购买流程可完成 | 两种商品整车下单 → 待支付 → 模拟支付 → 后台发货 → （P1）确认收货 |
| 交易失败可恢复 | 库存不足或中途异常时，无残留订单、无部分扣库存、购物车保留 |
| 状态与库存一致 | 重复支付不重复扣库存；重复取消不重复恢复；并发只产生合法结果 |
| 两端独立协作 | 用户端与管理端分别运行、分别登录，共同反映商品与订单变化 |
| 交付可复现 | 按 README 可在空库初始化并同时启动两端 |

### 1.3 非目标

不做真实支付、退款、物流、优惠券、积分、评价、收藏、推荐、多规格 SPU、地址簿、注册与找回密码、验证码、移动端适配、微服务与分布式库存。原型里出现过的这些按钮，一律删除或改为说明文字。

## 2. 角色与权限

| 角色 | 核心任务 | 权限边界 |
|---|---|---|
| 游客 | 看首页、按作品浏览、搜索、看商品详情 | 无购物车、无下单、无订单 |
| 普通用户 `CUSTOMER` | 登录、维护购物车、结算、查看本人订单、模拟支付、取消待支付订单、（P1）确认收货 | 只能访问本人的购物车与订单 |
| 管理员 `ADMIN` | 管理分类与商品、补货、查询全站订单、发货 | 只从管理端登录，不以管理身份在用户端购买 |

账号状态 `ENABLED` / `DISABLED`。受保护操作须同时满足：**身份 + 角色 + 启用状态 + 数据归属**。已持有 Session 的账号被禁用后，后续受保护请求也必须拒绝。

## 4. 功能需求

> 优先级：**P0** 必做；**P1** 选做（本项目全部选做）；**P2** 不做。

### 4.1 用户端 · 浏览

#### FR-G-00 欢迎入口与通用展示 `P1`

- 欢迎页保留品牌与两个入口：「账号登录」「先逛逛」。
- 移除注册、微信登录、"收藏/专属推荐"等原型宣传；无真实协议内容时不保留阻断浏览的勾选。
- 全局：人民币 `¥` 两位小数；搜索框提示「搜索商品名称」。
- 验收：游客能从欢迎页进入首页，再进入列表或详情，不被强制登录或注册。

#### FR-G-01 首页 `Main` `P0`

| 区块 | 要求 |
|---|---|
| 顶部导航与搜索 | 通用导航；搜索提交到列表页并回显关键字 |
| 品牌横幅 | 装饰图 + 品牌文案；「立即选购」进列表，不直接下单 |
| 作品入口 | 数据来自 `category` 的一级；显示 5 部作品，可进入该作品列表 |
| 新品上架 | 上架商品按 `created_at DESC, id DESC` 取 **3** 条 |
| 精选推荐 | 上架商品按 `sort_order ASC, id ASC` 取 **4** 条；全体游客一致，无个性化 |
| 商品卡 | 封面、名称、简介、人民币价格、详情链接；**移除卡片上的"＋"**，统一由详情页选数量 |
| 空状态 | 无上架商品显示「暂无上架商品」；缺图用统一占位图；数据库异常显示加载失败与重试 |

两栏允许同一商品重复出现，不去重。"更多"均进列表页。

#### FR-G-02 分类列表与搜索 `Category` `P0`

输入：一级分类 ID、类型 `productType`、排序 `sort`、关键字 `keyword`、页码 `page`、页大小 `pageSize`。

**分类与类型规则**

1. 左侧固定 5 个一级分类（= 5 部作品）。
2. 右侧按钮组：`全部 / 漫画 / 周边`，对应 `productType = ALL / COMIC / MERCH`。
3. 选中某个一级后，`全部` = 该作品下两个二级分类的并集；`漫画` = `-COMIC` 二级；`周边` = `-MERCH` 二级。
4. 未选一级时，类型过滤跨 5 部作品生效。
5. 切换分类、类型、排序、关键字，一律回到第 1 页。
6. 非法 `productType` 返回 400；排序值由服务端白名单映射，禁止接收任意 SQL 排序字段。

**搜索规则**

- 只按 `product.name` 做包含匹配；去首尾空白；最长 120 字符；空关键字等价于不搜索。
- `%`、`_` 按普通字符处理，不能作为用户自定义通配符。
- 不搜索 SKU。

**排序**（4 项）

| 值 | 排序 |
|---|---|
| `DEFAULT` | `sort_order ASC, id ASC` |
| `PRICE_ASC` | `price ASC, id ASC` |
| `PRICE_DESC` | `price DESC, id ASC` |
| `NEWEST` | `created_at DESC, id DESC` |

**分页**

- 商品列表页大小缺省 **6**，只允许 1–50 整数，越界或格式错误返回 400。
- 页码缺省 1，小于 1 的整数归一为 1；非整数或溢出返回 400。
- 页码超过末页：保留筛选，显示空结果 + 返回有效页入口，不自动换类。
- 记录数与总数使用同一套筛选条件。

**交互**

- 类型按钮与排序下拉在同一个 GET 表单里，选好后点「查询」整页刷新；不自动提交，不用 AJAX。
- 翻页是普通链接，保留分类、类型、关键字、排序、页大小。
- 商品卡展示封面、名称、简介、价格、库存/售罄状态；零库存仍可出现。
- 移除分类数量角标；"立即购买"改为"查看详情"；"到货提醒"改为"暂时缺货"。

#### FR-G-03 商品详情 `Product` `P0`

| 项 | 要求 |
|---|---|
| 定位 | 商品 ID（路径参数），展示不可变 SKU 与名称 |
| 分类路径 | 首页 / 一级 / 二级 / 商品，名称取数据库 |
| 价格与库存 | 当前价格两位小数；当前可销售库存；零库存显示售罄 |
| 图片 | 封面 + 相册，按 `sort_order ASC, id ASC`；无相册回退封面；缺失资源用占位图 |
| 描述 | 简介与纯文本详情，转义输出，保留合理换行 |
| 数量 | 默认 1，输入 1–99 整数，后端校验 |
| 加入购物车 | 游客先登录再返回商品，登录后由用户再次确认加入 |
| 返回列表 | 提供返回该作品列表的入口 |

不存在的商品、`DRAFT` 商品返回 404「商品不存在或已下架」。零库存可查看，但加入购物车与结算必须被后端拒绝。浏览不扣库存。移除多规格、付费服务、配送方式、收藏、"立即购买"、关联推荐。

### 4.2 用户端 · 账号

#### FR-U-01 登录与退出 `P0`

- 用户名：必填，去首尾空白，≤50 字符；按数据库用户名约定查询（不区分大小写唯一）。
- 密码：必填，不去除内部空格，不回显，不记日志；BCrypt 校验。
- 用户端只接受**启用状态的 CUSTOMER**。
- 登录成功后重建 Session（防会话固定），只存最小身份（用户 ID、显示名、角色、状态版本）。
- 跳转到合法的站内返回地址；登录失败统一提示「账号或密码错误，或账号不可用」，用户名可回显、密码不回显。
- 退出必须用 POST，使本端 Session 失效后返回公开页；数据库购物车不删除，管理端会话不受影响。
- 移除验证码、记住登录、找回密码、第三方登录、注册入口。

#### FR-U-02 身份与访问检查 `P0`

- 当前用户 ID 一律从服务端身份取，不信任表单里的 `user_id` 或 `role`。
- 每次受保护请求校验角色与状态；账号被禁用则拒绝。
- 越权时**不泄露目标对象详情与是否存在**，统一返回 404（AC-18 允许 403/404，本项目取更严的 404）。
- 登录返回地址限定站内路径，不得跳转外部地址，不得重放未确认的写请求。
- 两端 Cookie 名不同，可同浏览器分别登录，一端退出不影响另一端。

#### FR-U-03 个人资料 `P1`

只允许修改本人的 `display_name`（≤50）、`email`（≤100）、`phone`（≤30）。用户名、角色、状态不可由本人修改。不改写历史订单的收货快照。

#### FR-U-04 修改密码 `P1`

- 需验证旧密码；新密码与确认密码一致；不得与旧密码相同。
- 新密码 8–32 字符，UTF-8 不超过 72 字节，至少包含字母、数字、符号中的两类，不接受空白字符。
- 服务端执行全部校验；保存为 BCrypt 散列；成功后结束当前浏览器用户端 Session 并要求重登。
- 其他浏览器已有会话继续有效；历史订单、购物车不受影响。

### 4.3 用户端 · 购物车

#### FR-C-01 查询与加入 `P0`

1. 登录用户从详情页加入，服务端校验：商品存在、`ON_SALE`、数量为正整数、库存可用。
2. 同用户同商品只有一条记录，重复加入累加数量；单 SKU 合计 1–99，每车最多 20 种 SKU；校验累加后的值，不能只校验本次输入。
3. 成功后反馈结果，可继续选购或进入购物车；失败不修改原车。
4. 查询本人条目，关联**当前**名称、封面、价格、库存，重新计算行小计、数量总和、有效条目合计。
5. 购物车不预占库存、不保存可信价格；退出、会话失效、重启不清车。
6. 商品下架或售罄后条目仍保留，显示不可结算原因与移除入口，不自动丢弃。
7. 顶部徽标 = 本人全部 `cart_item.quantity` 之和（含失效条目），游客为 0。

#### FR-C-02 修改、移除与结算入口 `P0`

| 操作 | 行为 |
|---|---|
| 修改数量 | 按当前用户 + 条目 ID + 旧版本校验；新值 1–99 且校验库存；0 不代表自动删除 |
| 移除条目 | 按当前用户 + 条目 ID + 旧版本；成功后刷新合计，空车显示去选购入口 |
| 旧页面提交 | 条目已被其他会话修改时提示刷新，不覆盖新数量 |
| 去结算 | 车非空且全部条目可用才进结算；任一失效需先修正或移除 |

金额区只展示商品合计与应付总额（两者相同）。移除满减、优惠券、配送费、税费、勾选结算。

### 4.4 用户端 · 订单与支付

#### FR-O-01 结算确认 `Checkout` `P0`（新增页面）

- 前置：启用的 CUSTOMER 已登录，数据库购物车非空。
- 展示：当前全车商品、数量、单价、小计、总额，全部由后端计算。
- 收货人：必填，去首尾空白，1–50 字符。
- 联系电话：必填，去首尾空白，1–30 字符（不固定为 11 位手机号）。
- 详细地址：必填，去首尾空白，1–255 字符，单一完整地址文本。
- 后端临时确认：保存当前用户、条目 ID、商品 ID、数量、版本、价格到 Session。**打开确认页不锁价、不预占库存。**
- 提交前若车或价格变化，提示重新确认，不静默按新金额成交。
- 会话失效后重新登录并重新进入确认，不能用旧确认直接下单。

#### FR-O-02 创建订单 `P0`

提交时重新读取本人数据库全车，并验证确认快照、商品状态、数量、库存、价格。一次成功操作必须**同一事务**完成：

1. 新增一条 `PENDING_PAYMENT` 订单与至少一条明细；
2. 保存 SKU、名称、封面路径、单价、数量、行金额及收货信息快照；
3. 按数量扣减全部商品可销售库存，维护商品 `version`；
4. 删除本次已核对的结算条目，并校验清理结果。

任一点失败（商品不可用、库存不足、版本冲突、写入失败、注入异常）→ 整体回滚：无订单残留、无部分扣库存、购物车保留。

成功后清理临时确认，重定向到待支付订单详情。同一辆车并发提交只能成交一次。

#### FR-O-03 我的订单与订单详情 `P0`

- 列表只显示本人订单，按 `created_at DESC, id DESC`；支持 `全部 / 待支付 / 待发货 / 已发货 / 已完成 / 已取消` 与分页（默认 10 条）。
- 保留本人订单号搜索：完整订单号精确匹配，去首尾空白，≤40 字符，与状态筛选共同生效；空值不限制；查不到显示空状态；不支持按商品名搜索。
- 详情展示：订单号、创建时间、状态、收货快照、全部明细、数量与金额；已支付显示「教学模拟支付」、凭证与支付时间；已取消显示取消时间；已发货显示发货时间。
- 金额标签区分待支付「应付」与已支付「已模拟支付」。
- 待支付详情提供「模拟支付」「取消订单」；其他状态只提供合法操作。
- 统一五种状态文案，不使用"配送中""待收货"伪装物流。
- 商品改名、改价、换封面、下架后，历史订单仍显示创建时快照。

#### FR-O-04 取消待支付订单 `P0`

- 取消前二次确认，说明将关闭订单并释放库存。
- 服务端检查：订单属于本人且仍为 `PENDING_PAYMENT`；同一事务内转 `CANCELLED`、写 `cancelled_at`、按全部明细恢复库存并维护 `version`。
- 下架商品也恢复数量，但保持 `DRAFT`；取消不把商品放回购物车。
- 重复取消返回"已处理"，不再次增加库存；`PAID` 及之后状态不能取消。
- 中途失败时订单仍待支付，库存与版本回到取消前。

#### FR-O-05 确认收货 `P1`

仅订单所属用户可把 `SHIPPED` 转为 `COMPLETED` 并保存首次完成时间；重复请求不改变时间。这是教学状态确认，不代表物流签收。

#### FR-P-01 教学模拟支付 `P0`（新增页面）

1. 进入本人待支付订单的支付页，展示订单号、固定金额与「教学模拟支付，不涉及真实资金」。
2. 提供「模拟支付成功」「模拟支付失败」两个显式动作。
3. 成功：检查仍为待支付 → 转 `PAID`，写 `payment_method='MOCK'`、服务端生成的唯一 `payment_no`、首次 `paid_at`；**不再扣库存**。
4. 失败：仍为 `PENDING_PAYMENT`，不生成凭证，可重试或取消。
5. 重复成功：保持首次凭证与时间；已取消或不允许状态不能重新支付。
6. 金额只取订单总额；下单后商品涨价、下架不影响有效待支付订单的支付。
7. 操作后重定向回订单详情，展示数据库真实状态。

### 4.5 管理端

#### FR-A-01 管理员登录与控制台 `P0`

只接受启用的 `ADMIN`，密码校验、会话更新、退出规则与用户端一致，但 Cookie 与身份独立。`CUSTOMER` 不能从管理端登录。控制台只显示当前管理员与分类/商品/订单导航，不显示任何伪造统计。

#### FR-A-02 两级分类维护 `P0`

| 操作 | 规则 |
|---|---|
| 列表 | 层级、名称、编码、父分类、排序、操作 |
| 新增一级 | `code` 必填 ≤32，`name` 必填 ≤50，`parent_id` 空，排序非负 |
| 新增二级 | 选择存在的一级父分类；`code` 必须以 `-COMIC` 或 `-MERCH` 结尾 |
| 编辑 | 只改名称与排序；编码与父子关系不可变 |
| 删除 | 二次确认；有子分类或任意商品引用时拒绝（含下架商品） |

编码全局唯一，同级同名唯一，不同一级下可同名。禁止三级、自引用、循环。`code`、`name` 去首尾空白；唯一性按数据库不区分大小写处理。

#### FR-A-03 商品查询与维护 `P0`

列表支持一级/二级分类、名称、状态、分页；展示 ID、SKU、名称、分类、价格、库存、状态、排序。无结果给空状态；不保留销量列与删除按钮。

| 字段 | 新增与编辑要求 |
|---|---|
| SKU | 新增必填 1–40 字符、唯一、创建后不可改 |
| 商品名 | 必填 1–120 字符 |
| 所属分类 | 必填且为存在的二级分类 |
| 价格 | 必填 >0，最多两位小数，不超 `DECIMAL(12,2)` |
| 初始库存 | 新增时非负整数；编辑页只读 |
| 简介 | 可空，≤500 |
| 描述 | 可空纯文本，转义展示 |
| 封面路径 | 非空站内资源路径，≤255 |
| 排序 | 非负整数，默认 0 |
| 状态 | 新增默认 `DRAFT`，完善后显式上架为 `ON_SALE` |
| 版本 | 编辑页携带当前 `version`，保存时校验；用户不能指定新版本值 |

所有商品写操作（资料、价格、上下架、补货、下单扣减、取消恢复）都必须维护 `version`。旧表单保存返回冲突，提示「商品已发生变化，请刷新后重试」。

#### FR-A-04 库存查询与增量补货 `P0`

- 补货表单只要求商品标识与增加数量（正整数）。
- 成功后在**数据库最新库存**上增加，维护 `version`，反馈实际结果。
- 不提供"调整为指定库存值"或后台扣减入口；编辑页库存只读。
- 输入非法、商品不存在、溢出时不改变数据。

#### FR-A-05 全站订单查询与详情 `P0`

按订单号、五种状态筛选、分页，列表按创建时间与 ID 倒序。订单号精确匹配，≤40 字符。详情读取订单与明细快照，展示所属用户、收货信息、总额、状态、时间与 MOCK 凭证；不能编辑金额、明细、凭证或任意改状态。

#### FR-A-06 发货 `P0`

仅 `PAID` 订单显示发货操作。管理员确认后，服务端再次检查身份与状态，成功转 `SHIPPED` 并写首次 `shipped_at`，不改金额、库存与支付信息。重复发货提示已处理并保持首次时间。不录入物流公司与运单号。

#### FR-A-07 用户与相册管理 `P1`

- 用户管理：按用户名包含匹配 + `ENABLED/DISABLED` 筛选，默认按 ID 升序分页，只返回 `CUSTOMER`；启停前确认，后端按目标用户 ID 与角色校验；重复启停提示当前状态。
- 相册维护：按商品查看/新增/编辑/删除图片记录，默认按 `sort_order ASC, id ASC`；`image_path` 必填 ≤255，`alt_text` ≤120，`sort_order` 非负；删除只删记录不删文件，不改 `cover_image`；无相册时详情回退封面。
