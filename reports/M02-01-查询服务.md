## 1. 这次做了什么

把"页面查什么"收敛成一个服务，所有非法参数在服务层转 400：

| 文件 | 作用 |
|---|---|
| `common/page/PageResult.java` | 分页结果 record（items / total / page / pageSize + 派生方法） |
| `catalog/dto/ProductSearchCommand.java` | 列表原始参数（全是字符串，交给 Service 归一） |
| `catalog/dto/ProductDetail.java` | 详情视图：商品 + 两级分类 + 相册 |
| `catalog/service/CatalogService.java` | 列表查询、详情、分类树 |

## 2. 四个设计点

### 2.1 Controller 不解析参数，全部交给 Service

`ProductSearchCommand` 里的字段全是 `String`。Controller 原样绑定，Service 负责：

```
页码归一 → 页大小 1–50 → 类型白名单 → 排序白名单 → 关键字去空白/限长 → LIKE 转义
```

好处是只有一处会把"脏输入"变成 400，单测可以直接构造 `command.setSort("PRICE")` 这种脏值。

### 2.2 用户输入里的 `%` `_` 必须转义，否则会变成通配符

```java
static String escapeLike(String keyword) {
    return keyword.replace("\\", "\\\\")
            .replace("%", "\\%")
            .replace("_", "\\_");
}
```

不转义的话，用户搜 `%` 会匹配全部商品，搜 `_` 会匹配任意单字符——看起来像"搜索失灵"，实际是 SQL 通配符生效了。MySQL 的 LIKE 默认转义符是反斜杠，所以只转义、不改 SQL。

### 2.3 "不存在"和"已下架"都返回 404

```java
if (product == null || !"ON_SALE".equals(product.getStatus())) {
    throw BizException.notFound("商品不存在或已下架");
}
```

如果下架返回 403 或单独文案，就等于告诉别人"这个 ID 存在，只是下架了"。统一 404 符合 04 篇 §1 的"不泄露目标对象"。

### 2.4 分页结果用 record，派生方法不放 Service

`totalPages()`、`hasNext()` 这类派生值属于"分页结果"本身，放在 `PageResult` 里，模板直接 `${page.hasNext()}`，不用在 Controller 里算。

## 3. 又修了一个环境问题：Mockito 在 JDK 27 上起不来

第一次跑单测，10 个用例全部报：

```
java.lang.IllegalStateException: Could not initialize plugin:
interface org.mockito.plugins.MockMaker (alternate: null)
```

原因：Mockito 默认的 inline mock maker 依赖运行期自附加（self-attach）代理，JDK 27 上这条路走不通。

修复：在 `cartoon-catalog/src/test/resources/mockito-extensions/` 放一个文件

```
文件名：org.mockito.plugins.MockMaker
内容：  mock-maker-subclass
```

subclass 模式不需要自附加，代价是不能 Mock final 类——我们的 Mapper 都是接口，不受影响。

**注意**：之后 M03/M04/M05 这些要用 Mockito 的模块，也要放同一个文件（或统一在 test-support 里提供）。这条已记入遗留。
