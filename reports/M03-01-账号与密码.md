## 2. 三个设计点

### 2.1 登录失败不区分原因

```java
if (!matched) {
    throw new BizException(ErrorCode.UNAUTHORIZED, "用户名或密码不正确");
}
```

账号不存在与密码错误返回同一句话、同一个 401，避免被用来枚举账号。

### 2.2 禁用账号单独给 403

密码对了但状态是 `DISABLED`，返回 403 与"账号已停用，请联系店长"——这类提示不涉及账号是否存在，可以明说。

### 2.3 注册先校验再散列

用户名格式、密码长度、唯一性都通过后才 `encode`；唯一性另有数据库唯一键兜底。注册出来的账号角色固定 `CUSTOMER`、状态 `ENABLED`。
