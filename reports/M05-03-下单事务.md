## 3. 三个设计点

### 3.1 锁顺序：车行 → 商品 id 升序 → 订单写入

先 `SELECT ... FOR UPDATE` 锁本人购物车行，把同一辆车的并发提交串行化；再按商品 id 升序
`lockByIds`，两个事务不会以相反顺序加锁。商品锁用 `deductStock` 的 `stock >= qty` 兜底，
影响 0 行就抛异常整体回滚。

### 3.2 "同一车只成交一次"落在删条目行数上

```java
int deleted = cartService.removeCheckedItems(userId, lines.stream().map(CartLine::getItemId).toList());
if (deleted != lines.size()) {
    throw BizException.conflict("购物车已变化，请重新确认");
}
```

第二个并发事务拿到锁时，车已被第一个事务删空，删条目返回 0 行 → 抛异常 → 订单、明细、库存全部回滚。

### 3.3 快照比对只比内容，超时单独判

`CheckoutService.matches(snapshot, CartSummary.of(lockedLines))` 只比条目、数量、版本、价格与总额；
超时由 `expired()` 单独判断并给出"确认已超时"文案，两种失败都是 409 但提示不同。
