## 2. 三个设计点

### 2.1 403 与 409 必须能分开

之前全局异常处理器只认 404，其余一律 400。越权应该是 403、旧页面应该是 409，
都变成 400 会让前端与验收无法区分"参数错了"和"数据变了"。这次改成按错误码取状态码。

```java
response.setStatus(e.code().status());
```

### 2.2 旧页面不能覆盖新数量

改数量与移除都要求表单带回打开页面时的 `version`：

```sql
UPDATE cart_item SET quantity = ?, version = version + 1
WHERE id = ? AND user_id = ? AND version = ?
```

两个标签页同时改同一行时，只有先提交的那个成功，后一个拿到 409 与"请刷新后重试"，
不会把先提交的数量悄悄覆盖。

### 2.3 失效行保留并拦住结算

失效原因在查询时算：`DRAFT` → "已下架"，`quantity > stock` → "库存不足，仅剩 n 件"。
失效行仍计入页头徽标与"共 N 件"，但不计入可结算件数与总额，页面把"去结算"禁用并给出原因。
不自动删除：用户需要看到自己加过什么，再决定换货还是移除。
