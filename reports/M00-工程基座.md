## 1. 这一部分是做什么的

把原来"一个 pom + 一堆演示代码"的空壳，改造成**可编译、可测试、依赖方向可控**的多模块骨架，让后续每个业务模块都能独立构建与验证。

**范围内**

- 父 POM：统一 Java 版本、内部模块依赖管理、MyBatis-Plus 版本。
- 9 个模块骨架与目录约定。
- `cartoon-common` 的三个基础件：统一异常、分页参数、金额工具。
- 两个可启动的 Spring Boot 应用（用户端 / 管理端）与探活接口。
- 依赖边界检查：业务模块不得引入 Web starter。

**明确不做**

- 不写任何业务规则（商品、购物车、订单都留给 M01 之后）。
- 不建表、不连数据库、不写 Mapper。
- 不做页面模板（`/health` 只是探活）。

## 2. 设计与取舍

### 2.1 用一个多模块仓库，而不是两个独立工程

- **做法**：单仓库 9 模块，两个 `*-web` 模块各自 `spring-boot-maven-plugin`、各自 `application.yaml`。
- **为什么**：业务规则（分类校验、购物车上限、下单事务）两个应用都要用；拆成两个工程就得复制一份或发布私有 JAR。单人开发复制两份必然漂移。
- **放弃的方案**：严格两个独立工程（课程视频结构）。代价是同一套规则写两遍，改一处漏一处。

### 2.2 `common` 里只放"没有业务含义"的东西

- **做法**：`ErrorCode`、`BizException`、`PageQuery`、`MoneyUtils`；Spring Web 与 Servlet API 都以 `provided` 引入，不向下游传递。
- **为什么**：一旦 `common` 里塞进商品或订单的类，所有模块都会被动依赖它，模块边界就废了。
- **放弃的方案**：把 `SessionUser`、CSRF 过滤器也放进 `common`。它们依赖 Servlet API，会让 `common` 变成 Web 模块；M03 再决定放 web 层还是单独拆模块。

### 2.3 用 enforcer 守住依赖方向，而不是靠自觉

- **做法**：父 POM 绑定 `maven-enforcer-plugin`，`bannedDependencies` 排除 `spring-boot-starter-webmvc`；两个 web 模块用 `enforcer.skip=true` 放行。
- **为什么**：人一定会偷懒——某天在 `cartoon-cart` 里想返回 `ModelAndView`，加个 web 依赖就编过了。构建期红一次，比评审时争论有效。
- **放弃的方案**：ArchUnit 测试。能力更强，但要额外依赖且只在测试期生效。

### 2.4 分页与金额工具先落地

- **做法**：`PageQuery` 统一页码/页大小归一；`MoneyUtils` 统一两位小数与超精度拒绝。
- **为什么**：这两个是**跨模块重复率最高**的逻辑。04 篇规定了 400 的判定口径，如果每个 Controller 自己写，必然出现"有的地方 0 归一到 1、有的地方报错"。
- **放弃的方案**：放到各模块里各写一份。

## 4. 代码逐行对照

### 4.1 `PageQuery#of` 与两个解析方法（第 35–73 行）

| 行 | 代码 | 说明 |
|---|---|---|
| 35 | `public static PageQuery of(String rawPage, String rawPageSize, int defaultPageSize)` | 唯一入口：Controller 只调它，不自己 `Integer.parseInt` |
| 36 | `int page = parsePage(rawPage);` | 页码归一 |
| 37 | `int pageSize = parsePageSize(rawPageSize, defaultPageSize);` | 页大小校验 |
| 38 | `return new PageQuery(page, pageSize);` | 紧凑构造器会再兜一次底（19–26 行） |
| 47 | `if (raw == null \|\| raw.isBlank()) return 1;` | 缺省 1，空串等同于没传 |
| 52 | `value = Integer.parseInt(raw.trim());` | 去空白再解析 |
| 53–54 | `catch (NumberFormatException e) { throw BizException.badRequest("页码必须是整数"); }` | 非整数、溢出都走 400，不抛 500 |
| 56 | `return Math.max(value, 1);` | 0、负数归一为 1（04 篇 §4 的口径） |
| 60–62 | 空白 → `requireValidDefault(defaultPageSize)` | 缺省值本身也要合法，防止调用方传 0 或 99 |
| 69–71 | `if (value < MIN_PAGE_SIZE \|\| value > MAX_PAGE_SIZE) throw ... 400` | 1–50 之外一律拒绝，不静默截断 |
| 76–78 | 默认值越界抛 `IllegalArgumentException` | 这是**程序错误**不是用户输入错误，所以不走 400 |

**关键点**：页码"小于 1 归一"和页大小"越界报错"是两种不同处理——前者用户常犯且无歧义，后者会掩盖前端 bug。这条差异在 04 篇 §4 写死了，测试 `pageBelowOneIsNormalized` 与 `pageSizeOutOfRange` 分别覆盖。

### 4.2 `MoneyUtils#parse`（第 28–45 行）

| 行 | 代码 | 说明 |
|---|---|---|
| 29–31 | `if (raw == null \|\| raw.isBlank()) throw 400 "不能为空"` | 空值先拦住，避免 `new BigDecimal("")` 的异常信息泄露 |
| 34 | `value = new BigDecimal(raw.trim());` | 用字符串构造，**绝不用 double** |
| 38–40 | `if (value.signum() <= 0) throw "必须大于 0"` | 价格、数量金额都不允许 0 或负 |
| 41–43 | `if (value.stripTrailingZeros().scale() > 2) throw "最多两位小数"` | 先去掉尾随 0，`28.000` 合法、`28.999` 拒绝 |
| 44 | `return value.setScale(SCALE, RoundingMode.UNNECESSARY);` | 兜底：scale 不为 2 时直接抛，而不是四舍五入 |

**关键点**：`RoundingMode.UNNECESSARY` 是故意的。金额一旦被静默舍入，账就对不上；宁可抛异常让上游拒绝这笔业务。测试 `parseTooPrecise` 断言 `28.999` 被拒。

### 4.3 依赖边界（`pom.xml` 第 88–111 行）

```xml
<bannedDependencies>
    <excludes>
        <exclude>org.springframework.boot:spring-boot-starter-webmvc</exclude>
    </excludes>
    <message>业务模块不得依赖 Web starter：Web 依赖只允许出现在 cartoon-user-web / cartoon-admin-web</message>
</bannedDependencies>
```

**为什么放在父 POM**：所有模块继承同一条规则，新增模块自动受约束；web 模块用 `<enforcer.skip>true</enforcer.skip>` 单独放行，不需要逐个配置例外。
