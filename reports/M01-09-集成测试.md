## 2. 关键设计

### 2.1 用"数据命名空间"避免同级重名

`category` 有 `uk_category_sibling_name(parent_key, name)`：同一个父下不能同名，一级分类之间也不能同名。第一版每个测试都建一个叫「测试作品」的一级分类，第二个测试就撞名了。

改成每个测试用不同的后缀：

```java
private long newSecondaryCategory(String codeSuffix) {
    long primaryId = insertPrimaryCategory("IP-" + codeSuffix, "作品-" + codeSuffix);
    return insertSecondaryCategory("COMIC-" + codeSuffix, primaryId, "单行本");
}
```

### 2.2 CHECK 违规在 Spring 里不是 `DataIntegrityViolationException`

MySQL 的 CHECK 报错码是 **3819**、SQLState `HY000`，Spring 的 `SQLExceptionSubclassTranslator` 不认识，包装成 `UncategorizedSQLException`（`DataAccessException` 的子类）。

所以断言写成：

```java
.isInstanceOf(DataAccessException.class)
.hasMessageContaining("Check constraint");
```

如果硬断言 `DataIntegrityViolationException`，测试会以"类型不符"失败——第一版就是这么挂的。

### 2.3 断言落在真实行为上

不 Mock Mapper，直接查库：

```java
assertThat(productMapper.deductStock(productId, 2)).isZero();   // 库存 1，扣 2 失败
assertThat(productMapper.deductStock(productId, 1)).isEqualTo(1);
assertThat(jdbc.queryForObject("SELECT version FROM product WHERE id = ?", Long.class, productId)).isEqualTo(1L);
```

## 3. 一个必须记下来的问题：Lombok 在 JDK 27 上静默失效

第一次跑测试，编译报 `找不到符号: getCategoryName()`。排查发现：**实体和 DTO 编译后根本没有 getter**，但构建一直"成功"——因为之前没有任何代码调用它们。

原因：**JDK 23 起默认关闭隐式注解处理**，只把 Lombok 放在 classpath 上不够，必须在编译器里显式声明处理器。

修复（父 POM）：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <proc>full</proc>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>
```

修复后 `javap` 能看到 `getProductName()` 等方法。

**这个坑的教训**：编译通过不等于代码可用。M01-06 提交实体时"BUILD SUCCESS"，其实全是没有 getter 的空类；直到 M01-09 第一次调用才暴露。之前几个任务的验证只做到编译，这次补上了运行期证据。
