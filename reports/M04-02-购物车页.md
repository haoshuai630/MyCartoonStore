## 2. 三个设计点

### 2.1 徽标放在拦截器里，不在每个 Controller 里塞

```java
int count = userId instanceof Long id ? cartService.badgeQuantity(id) : 0;
modelAndView.addObject(MODEL_KEY, count);
```

页头片段被所有页面复用，逐页 `model.addAttribute` 一定会漏。拦截器统一在渲染前查一次，
重定向不渲染页面就直接跳过，省一次求和。

### 2.2 游客加车回详情页，而不是回 POST 地址

`POST /cart/items` 被拦截后若照旧带 `redirect=/cart/items`，登录完会以 GET 请求一个只接受 POST
的地址，得到 405。这里对 POST 请求改取同源 Referer 的路径，登录后回到详情页，用户再点一次
——与 05 篇写的交互一致。Referer 必须协议、主机、端口全对上，避免被构造成站外跳转。

### 2.3 页面不做金额乘法

合计、行小计都在 `CartSummary`/`CartLine` 里用 `MoneyUtils` 算好，模板只做格式化输出。
模板里出现乘法，迟早会出现"页面显示的总额和下单金额不一致"。
