## 1. 模块目标与范围

**目标**：把"购物车 → 确认订单 → 生成订单 → 查看/取消订单"这条链路打通，
金额只由服务端计算，订单保存成交快照，商品改价/下架不影响历史订单。

**范围内**：
- 结算确认页与 10 分钟确认时限
- 原子下单：写订单 + 写明细 + 扣库存 + 删结算条目
- 订单列表（状态页签、单号搜索、分页）与详情（时间线、快照）
- 取消待支付订单并恢复库存（幂等）

**明确不做**（留给后续）：
- 模拟支付与支付凭证（M06）
- 管理端改状态/发货（M07）
- 列表卡片上的支付/取消按钮（M06 一起补）
- CSRF 防护（M09）

## 4. 架构位置与关键设计

```
user-web  CheckoutController / OrderController
              │
              ▼
cartoon-order  CheckoutService / OrderService / OrderListService / OrderQueryService
              │                    │
              ▼                    ▼
        cartoon-cart          cartoon-catalog
        （锁车、删条目）        （锁商品、扣/恢复库存）
```

1. **快照只作确认凭据**：确认页把条目、数量、版本、单价写进 `CheckoutSnapshot` 存 Session，
   提交时重新读库逐项比对；不一致 409，绝不按快照价成交。
2. **10 分钟确认时限**：`expired()` 用注入的 `Clock` 判断，恰好第 10 分钟算过期；
   超时与"车已变"都是 409，但文案不同。
3. **锁顺序固定**：车行（`FOR UPDATE`）→ 商品 id 升序 → 订单写入；
   取消则锁订单行，再逐条恢复库存。
4. **同一车只成交一次**：删结算条目的影响行数必须等于核对条数，否则回滚；
   AC-17 用两线程同时提交验证只成交一单。
5. **取消幂等**：第二次取消看到 `CANCELLED` 直接返回，不再恢复库存；
   库存恢复与版本递增同一条 SQL，与下单扣减对称。
