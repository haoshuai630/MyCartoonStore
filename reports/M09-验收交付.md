**目标**：把 M00–M08 做出来的系统"交付出去"——补上最后两项横切防护，拿出可复查的并发与复现证据，
写清需求完成清单、验收记录与实验报告，全量回归后合并 `main` 并打 tag。

**范围内**：

- CSRF 同步令牌（AC-31）：公共件 `CsrfToken`/`CsrfFilter`、两端注册与 403 页面、29 处写表单、测试夹具与页面级用例
- 用户端登录重建会话（FR-U-01）：`changeSessionId()`，与管理端同构
- 商品描述 ≤2000、封面只收 `images/` 站内路径（M08 审阅留下的复核项）
- AC-28 两端并发证据（买 2 + 补 3 → 库存 11）
- AC-32 空库复现证据（备份 → 重建 → 核对 → 恢复）
- 交付文档：`docs/13-需求完成清单.md`、`reports/M09-验收记录.md`、`reports/M09-实验报告.md`
- 清点时补 2 条缺口用例：AC-18 他人订单详情 404、AC-22 下架后取消

**明确不做**：

- Spring Security 全栈、CSP/HSTS、点击劫持响应头、登录限流
- 图片上传与文件删除、外链图片、真实漫画 IP（docs/12）
- 改密后踢掉其他浏览器（FR-U-04 明确只结束当前会话）
- 新业务功能、页面改版、表结构变更、CI/CD、压测

## 3. 设计与取舍

### 3.1 令牌只存会话，缺令牌等于拒绝

不引入 Spring Security，只做同步令牌：会话键 + 表单参数 + 恒定时间比较。最容易写错的 `if (token == null) return true` 被单测钉死。
放弃双提交 Cookie：多一个可被 JS 读取的 Cookie，两端同名还会互相覆盖。

### 3.2 一处渲染，不逐表单手写

29 处写表单都引用同一个隐藏域片段。手写 29 个 `<input>` 迟早漏一处，而漏掉的表现是"某个按钮点了 403"。

### 3.3 403 用独立模板，并用两种方式验证

`sendError(403)` 在真实容器里走 `error/403`，MockMvc 不走错误分发。于是分两层验：MockMvc 断言状态码，
另用 `/error` + `Accept: text/html` 断言页面文案，真实容器的分发再由探针脚本覆盖。

### 3.4 会话重建用 `changeSessionId()`

`invalidate()` + 新建会丢掉 CSRF 令牌与回跳参数，`changeSessionId()` 换 ID 保属性，防护效果一致，且与管理端 M07-02 同构。
用例不只断言 ID 变了，还断言"换 ID 后登录前签发的令牌仍可用于退出"。

### 3.5 证据以请求/响应 + SQL 为准

AC-28 与 AC-32 都是脚本化取证：前者两个 JVM 并发，后者按交付脚本重建库再启动两端。
不做浏览器截图（本环境无法操作浏览器），因此视觉类验收在验收记录里单列"需人工看图"，不假装有证据。
