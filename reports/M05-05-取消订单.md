## 2. 这次做了什么

| 产出 | 内容 |
|---|---|
| `OrderService.cancel` | 锁订单行 → 归属 404 → 已取消幂等返回 → 非待支付 409 → 改状态 → 逐条恢复库存 |
| `ProductMapper.restoreStock` | `stock = stock + qty, version = version + 1` |
| `OrderController` | 新增 `POST /orders/{orderNo}/cancel`，成功/幂等两种提示 |
| `order-detail.html` | 待支付显示「取消订单」按钮与"车不会自动回填"提示 |

**幂等的实现**：第二次取消在 `CANCELLED` 分支直接 `return false`，不会再走恢复库存；
测试里第二次取消后库存仍为 10、版本仍为 1，详情页提示"订单已取消，无需重复操作"。

## 3. 三个设计点

### 3.1 锁订单行，而不是锁商品

取消只影响一张订单：`SELECT ... FOR UPDATE` 锁 `sales_order.order_no` 行，
并发的取消/支付会在这一行上排队；第二个取消看到 `CANCELLED` 直接返回。
商品库存随后逐条 `UPDATE`，不需要预先锁商品（恢复没有"库存不足"约束）。

### 3.2 库存恢复与版本递增同一条 SQL

```sql
UPDATE product SET stock = stock + #{qty}, version = version + 1 WHERE id = #{id}
```

与下单的 `deductStock` 对称：每次取消只加一次，版本变化还能让购物车里的旧行失效。

### 3.3 购物车不自动回填

取消只恢复库存，不把明细写回 `cart_item`——这是 FR-O-04 的明确要求。
测试 `cancelPendingOrderRestoresStockOnce` 断言取消后 `cart_item` 仍为 0。
