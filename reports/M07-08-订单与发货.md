## 2. 这次做了什么

- **订单模块**：`OrderAdminService`（全站列表 + 详情 + 明细）、`ShipService`（行锁 + 只允许 PAID + 重复发货幂等）、`AdminOrderPage`、`ShipResult`。
- **账号模块**：`AccountService.displayNames(ids)` 批量取显示名，后台列表一次查完。
- **管理端**：`AdminOrderController` 三条路由；`order-list.html`（筛选 + 列表 + 翻页）、`order-detail.html`（明细快照、收货、支付与时间、发货按钮）。
- **入口**：导航加「订单处理」，控制台订单卡片接成链接；三个入口全部可用。
- **实体**：`SalesOrder.getStatusLabel()` 让模板直接显示中文状态，不在页面写映射。

**没有做的**：后台改金额/明细/凭证/状态（FR-A-05 明确禁止）、物流公司与运单号（FR-A-06 明确不录入）、确认收货（M08）。

## 3. 关键设计

### 3.1 发货只认 PAID，重复发货不改时间

`ShipService` 先锁订单行：`SHIPPED`/`COMPLETED` 直接返回"已处理"，不写库；
`PENDING_PAYMENT`/`CANCELLED` 返回 409；只有 `PAID` 才迁移并写首次 `shipped_at`。
这样两个管理员同时点发货，第二个不会把时间改晚。

### 3.2 所属用户由 web 层装配，不破坏模块边界

`order` 模块不依赖 `account`（docs/09 §2.3）。列表页把本页的 `userId` 去重后调
`AccountService.displayNames()` 一次查完；详情页只查一个。

### 3.3 详情页完全只读

金额、明细、支付信息、状态都没有输入框或按钮；唯一可写动作是"发货"，且只在 `PAID` 出现。
这直接对应 FR-A-05 的"不能编辑金额、明细、凭证或任意改状态"。

### 3.4 模板分区说明（docs/10 §5：模板用手工表）

**`order-list.html`（约 100 行）**

| 区块 | 说明 |
|---|---|
| 标题区 | 「订单处理」+ 只读说明 |
| 筛选条 | 完整订单号（≤40）+ 五种状态 + 查询/重置 |
| 列表 | 订单号、所属用户（`users.get(userId)`）、创建时间、状态标签、金额、详情入口 |
| 翻页 | 保留 `orderNo` / `status` |
| 空状态 | 没有符合条件的订单 |

**`order-detail.html`（约 130 行）**

| 区块 | 说明 |
|---|---|
| 面包屑 | 订单处理 / 订单号 |
| 头部 | 状态标签、订单号、创建时间、所属用户；`PAID` 时出现「发货」按钮（带二次确认） |
| 明细表 | 封面、名称、SKU、单价、数量、行金额（全部取快照） |
| 金额 | 订单总额只读 |
| 收货信息 | 收货人、电话、地址（快照） |
| 支付与时间 | 支付方式/凭证/支付时间、发货时间、取消/完成时间（按有无显示） |

**`admin.css`**：只追加订单详情的两列布局、明细行、键值列表与总额行，不逐行对照。
