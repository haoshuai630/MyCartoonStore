## 3. 关键设计

### 3.1 `product_id` 用 SKU 子查询，不依赖自增

```sql
((SELECT id FROM product WHERE sku='STARLINE-C01'), 'images/products/STARLINE-C01/1.svg', ...)
```

商品是自增主键，脚本里没写死 id。若用"第 N 行对应 id=N"的假设，任何顺序调整都会静默错位；子查询把关联关系显式写出来，读 SQL 的人也能一眼核对。

代价是 100 条各带一个子查询，初始化几秒内完成，可接受。

### 3.2 3 / 2 / 0 的分布按位置算，不按名称点

```python
pos = idx % 12
count = 3 if pos < 4 else (2 if pos < 8 else 0)
```

`build_products()` 的输出顺序固定（每部作品 6 卷 + 6 周边），所以 `idx % 12` 就是"这部作品里的第几件"。按名称点（比如"每部作品的第 3 件 2 张"）在改商品名时会失效。

### 3.3 为什么不用 `INSERT ... SELECT` 一次生成

可以用笛卡尔积生成 1–3 张，但"第几件几张"这种非均匀规则会写成很难读的 `CASE`。逐行生成虽然 SQL 长，但与验收标准一一对应，出错时能直接定位到某一行。

### 4.3 路径与排序

`image_path` 一律 `images/products/{sku}/{n}.svg`，`sort_order` 就是 `n`，详情页按 `sort_order, id` 升序取图时顺序即 1→2→3。
